**완료 증거가 *"같은 오염 샘플에서 새 게이트는 실패하고 기존 게이트는 통과한다"* 형태이면, 오염의 *모양* 자체가 설계 사항이다.** 후보·방식만 정하고 오염 형태를 implementer에게 맡기면 증거가 무효가 된다.

**Why:** T116(§39, 2026-07-29). 요구는 *"컴포넌트가 필드를 안 그리는 오염에서 새 렌더 게이트는 실패, G76·AC-079는 통과"*. 그런데 **G76은 컴포넌트 소스에 카탈로그 문구 리터럴이 있는지만 본다**(`mockScreenCopy.test.ts:345`). ⇒ **문구 리터럴을 지우는 오염을 만들면 G76이 그것을 잡아 버려 요구가 뒤집힌다.** 상류 태스크 명세도 §32도 이 제약을 적지 않았다 — 방식 판정에만 집중해서 놓친 자리다.

**How to apply:**
- 오염 유형별로 **⛔ 잘못된 형태 / ✅ 올바른 형태** 2열 처방표를 절에 넣는다. 일반형: **기존 게이트의 입력은 한 바이트도 안 바뀌고, 새 게이트의 관측 대상만 끊긴다.** (렌더 층 예: 상수 리터럴은 남기고 **렌더 지점 표현식**만 치환)
- **"기존 게이트가 통과한다"를 다른 스위트 초록으로 갈음시키지 마라.** 기계적 형태 = **입력 불변 단언**(`카탈로그문구.filter(t => 원본.includes(t) !== 오염본.includes(t))` → `deepEqual([])`). 이 관용구는 `mockScreenCopy.test.ts:200-209`가 이미 세워 뒀다.
- 축이 2개(존재/순서)면 **각 축만 단독으로 빨강이 되는 오염**을 따로 요구한다. 둘 다 빨강이면 두 번째 축이 사실은 첫 번째를 다시 하고 있는 것이다.
- 오염을 로더/훅의 **오버라이드 맵**에 주입하면 정상·오염이 같은 수단을 타 [[feedback_negative_test_flips_the_method]]의 G139류 요구가 구조적으로 충족된다. 디스크 사본·실파일 수정·되돌리기는 금지(되돌리기 실패 사고 선례).
