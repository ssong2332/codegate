문서의 **예시**와 **규범 규칙**이 구현과 어긋날 때, 정본은 **규범 규칙**이다. 규칙을 좁히지 말고 **예시를 고친다.** 특히 게이트·검사기의 "못 잡는 형태" 목록에 **실제로는 잡히는 것**을 적어 두는 과소 서술은, 못 잡는 것을 빠뜨리는 과대 서술만큼 결함이다.

**Why:** 게이트를 실제보다 약하게 보이게 하면 다음 사람이 "이것도 못 잡네"라며 **불필요한 확장**(데이터 흐름 분석 등)을 시도하고, 그 확장은 오탐을 늘려 결국 게이트 자체가 삭제된다. 반대 방향(과대 서술)은 잘못된 안심을 준다. 2026-07-27 T108 정정에서 reviewer가 같은 판정을 냈고 사용자가 그 판정을 그대로 넘겨줬다.

**How to apply:**
- 문면-구현 불일치를 받으면 **인용으로 판정하지 말고 병합된 코드를 직접 읽어** 어느 쪽이 사실인지 먼저 확정한다.
- 규칙을 좁혀야 한다는 결론이면 코드 변경이 필요하므로 **직접 고치지 말고 implementer 인계**로 적는다.
- 한계를 넓힐지(검사 범위 확장) 여부는 **결정하지 말고 OQ로 등재**한다. OQ 번호는 planner 소유 문서에서 최대값+1로 **제안**만 하고 확정은 planner에 넘긴다.
- 정정한 자리에 **무엇이 왜 틀렸었는지**를 남긴다(원문 삭제 아님). 관련: [[upstream-breakage-counts-undercount]]
