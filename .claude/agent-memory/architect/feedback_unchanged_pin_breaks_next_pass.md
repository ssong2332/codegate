상수를 바꾸는 설계에서 "갱신할 정확 일치 사본" 목록만 적으면 빠지는 것이 있다: 이전 패스가 "이번엔 이 상수를 안 바꿨다"를 고정하려고 넣은 단언(예: T192 C7 때 `hangupToolFirst.test.ts:114` — TOOL 공통 머리 = 옛 정본 `G616_OLD_TOOL`의 머리). 이건 사본이 아니라 역검증용 옛 정본과의 비교라서, 옛 정본을 고치면 역검증이 죽고, 안 고치면 빨개진다.

**Why:** C7 설계 초안이 "사본 4개 갱신"이라고 적었는데, 열어 보니 그중 하나(SIGNAL 사본)는 없었고, 대신 무변경 고정 단언 1줄이 반드시 실패하게 돼 있었다. implementer가 이걸 "역검증 사본도 갱신"으로 처리하면 게이트가 조용히 죽는다.

**How to apply:** 상수를 바꾸기 전에 그 상수의 부분 문자열(문장 몇 개)을 tests 전체에서 grep해 히트마다 성격을 분류한다: ① 정확 일치 사본 → 새 정본으로 ② 역검증용 옛 정본 → 무편집(바꾸면 역검증이 죽는다) ③ "옛 정본과 같다" 고정 단언 → 기준값만 새 정본으로 교체(의미 변경 — 체크리스트에 명시). [[norm-beats-example]] [[correction-sweep-reuse-sites]]
