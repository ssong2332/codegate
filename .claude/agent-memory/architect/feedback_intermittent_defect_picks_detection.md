**결함이 간헐적이면, 원인 제거(②)가 아니라 결과 검출(트립와이어 ①)을 무조건 채택하고 원인 제거는 "결정적 재현 프로브"에 건다.**
그리고 상류가 *"고친 뒤 1회 돌려서 깨끗하면 완료"* 를 요구했다면 **그 요구 자체를 정정하라.**

**Why:** T130(`npm install`이 `package.json`에 `"file:.."` 주입)에서 상류 태스크 행 G항 ④가
*"`npm install` 실행 후 `git status`가 깨끗함을 보이라"* 를 완료 증거로 요구했다. 그런데
implementer 1인칭 기록이 **"항상 나지도, 안 나지도 않는다"**(간헐)를 남기고 있었다 —
⇒ **고치지 않아도 깨끗한 회차가 자연히 나온다.** 그대로 따랐으면 오보를 만드는 명세였다.
반대로 트립와이어는 **원인을 몰라도 성립하고 검증이 결정적**이다: 오염 사본을 *내 손으로 만들어*
거부되는지 보면 되기 때문에, **원인 프로브가 실패해도 산출물이 남는다.**

**How to apply:**
1. 상류가 준 증상 기록에서 **"매번 나는가"를 먼저 찾아라.** 1인칭 기록에 *"이번엔 안 났다"* 가
   한 줄이라도 있으면 간헐로 취급한다(분모 없는 "N회 발생"은 빈도가 아니다).
2. 간헐이면 방식 순위가 뒤집힌다: **원인 제거는 조건부 유보**, 검출은 무조건 채택.
   근거 문장은 항상 같다 — *"②는 원인을 알아야 착수하고 '안 났다'로 검증되지 않는다.
   ①은 원인을 몰라도 성립하고 검증이 결정적이다."*
3. 원인 제거를 착수하는 경우의 증거는 **"수정 전 N/N → 수정 후 0/N (N≥3)"** 으로 못박고,
   **수정 전 수치를 먼저 기록**하게 하라(`CLAUDE.md` 보고 템플릿의 "이전/기준값" 열).
4. 원인을 규명 못 해도 **불변식은 확정할 수 있다** — T130에서는
   *"주입 이름은 항상 조상 패키지, 지정자는 항상 매니페스트→루트 상대 경로"* 를 확정해
   검출 규칙을 그 위에 세웠다. **가설은 표로 나열하고 어느 것도 채택하지 마라.**
5. ⛔ 원인 미규명을 *"미완"* 으로 보고하지 말 것 — 검출 채택이 완료 조건이다.
