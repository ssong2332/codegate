"사기범이 공회전만 하고 안 끊는다 → 판정표에 '공회전 N턴' 행을 둘지 검토하라"(T192 C6 F2, 2026-10-19). 판정표 10행 중 허용 행은 "막는 행에 안 걸림"의 결과뿐이었고, 끊기 개시는 모델 호출뿐이었다. 행을 더해도 모델이 부르지 않으면 효과 0이고, 서버가 강제하는 행은 PRD가 금지한 이유(시간·소강)를 서버가 판정하게 된다.

**Why:** 게이트에 행을 더하는 요청은 "막힌 것"과 "시작되지 않은 것"을 구분하지 않는다. 신고 증상(아무 일도 안 일어남)은 둘 다로 보인다. 같은 신고에 진짜 차단(열릴 수 없는 확인 오퍼가 4행을 영구히 켬 = R4)도 섞여 있었다.

**How to apply:** ① 표의 `hangup:true`/허용 행이 개시를 만드는지 확인 ② 증상 세션을 "호출 0"과 "호출+거절(row)"로 가르는 로그가 있는지 확인(폴백 사전 판정은 로그 0이었다 → 관측 1줄 추가) ③ 개시 층(문면·신호)과 차단 층(표)을 갈라 각각 처방. 차단 완화는 클라 값 금지·"이 경로에서 구조상 불가능한 칸"만. 관련 [[pending-flag-self-reference]] [[exception-bound-to-observable-event]].
