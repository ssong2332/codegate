외부 모델/서비스 상수를 고정(핀)하는 설계를 쓸 때는 **핀과 함께 지연 기준선 4값**(측정일 · 대상 id · 요청 조건 · 경과 ms)을 같은 자리에 요구하라. 핀만으로는 절반만 막힌다.

**Why:** codegate에서 같은 계열 사고가 두 번 났다. T98은 `-latest` 별칭의 **실체 재매핑**, §56은 **고정 id 자체의 서빙 지연**(3토큰 요청도 47초). 고정 버전 핀은 전자만 막고 후자엔 **정적 게이트가 영원히 초록**이다. 두 번째 사고에서 원인을 가른 유일한 근거는 누군가 상수 주석에 적어 둔 `2,959ms / 추론 269토큰`(2026-07-27) 한 줄이었다 — 그것이 없었으면 "47초가 원래 그런 것"과 구분 불가였다.

**How to apply:**
- 모델·외부 API 상수를 신설·교체하는 설계에는 기준선 기록을 **하드 요구**로 넣는다(없으면 반려).
- ⛔ 기준선을 **측정일 없이** 인용하지 마라 — 실제로 낡은 수치를 "오늘 값"으로 읽어 **잘못된 후보를 유력으로 순위 매긴** 사례가 있다(추론 토큰 가설).
- 후보 판정표를 쓸 때 **"우리 커밋 0줄인데 상대가 바뀌었다"** 행을 항상 살려 둘 것. 프롬프트·SDK·네트워크 축을 먼저 의심하면 처방이 자기 코드 훼손으로 간다.
- 관측 로그를 추가하는 안(A)을 "감지 장치"로 부르지 마라 — **읽는 주체(스모크/알림)** 가 없으면 기록만 쌓인다. [[feedback_intermittent_defect_picks_detection]]·[[feedback_indistinguishable_states_pick_the_signal]] 계승.
- 쿼터가 `PerProjectPerModel` 형태면 **모델 교체 = 예산 버킷 교체**다. 기존 예산 산술을 그대로 재사용하지 말 것.
