**전역 가드가 조건 불충족 시 `return null` / 리다이렉트하면, 그 순간 진행 중인 실시간 세션이 함께 죽는다.** 가드에 걸리는 처방(로그아웃·재인증 유도·차단)은 **한 덩어리로 쓰지 말고 "지금 어떤 화면인가"로 갈라** if/then 표를 만든다.

**Why:** T128(2026-07-28). 이 앱은 통화·문자·리포트가 한 세션으로 이어지는데, `RouteGuard`가 `user === null`이면 트리를 통째로 언마운트한다. 같은 저장소의 `session/play`는 *"early return·상위 래퍼·key 변경·router.push 중 어느 하나라도 하면 실시간 세션·마이크·타이머가 끊긴다"* 를 주석으로 못 박아 둔 파일이다 ⇒ **가드의 정상 동작이 곧 세션 파괴**였다.

**How to apply:**
- 최소 3분할: **훈련 밖(현행 유지·코드 0줄) / 진행 중(리다이렉트·언마운트 금지 + 비차단 배너) / 복구 불가 사용자(익명 등 — 재인증이 성립하지 않으므로 종료 안내)**.
- 예외는 **"지금 열려 있는 화면"에만** 붙이고 **라우트가 바뀌면 즉시 원 규칙으로 복귀**시킨다. 그래야 "미인증인데 보호 화면이 남는다"는 반대 논거를 좁게 막을 수 있다.
- 재인증 수단은 **페이지를 이탈하지 않는 것만**(popup ○ / redirect ✗). 리다이렉트 폴백이 기존 코드에 있어도 이 경로에서는 금지로 명시한다.
- 익명 인증은 **uid 재발급이 불가능**하므로 "재로그인 유도"가 성립하지 않는다 — 무로그인 진입을 약속한 AC가 있으면 로그인 화면으로 보내는 것 자체가 위반이다.
- 진행 중 예외에는 불변식을 함께 박는다: **새 서버 호출 0건**(그래야 "세션당 1리포트" 류 불변식과 진입 게이팅 AC를 동시에 지킨다).
