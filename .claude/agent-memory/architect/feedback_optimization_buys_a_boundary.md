**절감·통합·최적화 후보를 채택하기 전에, 그것이 지우는 *경계*가 무엇인지 먼저 적어라.**
합치기(함수·서비스·모듈 통합)는 단위 비용을 줄이는 대신 **최소권한 경계·격리·장애 단위**를
같이 지운다. 절감액이 **미확인**인데 대가가 **확정적**이면 그 교환은 성립하지 않는다.

**Why:** "무료 운영" 패스(2026-07-29, `docs/Architecture.md` §44)에서 *"함수 26개를 통합하면
컨테이너 이미지가 준다"* 는 순수한 비용 승리로 보였다. 그러나 **바로 앞 패스(§41/T133)** 가
정합화한 시크릿 선언 경계 — 12개 핸들러 중 **5곳만** API 키를 선언한다 — 가 통합으로 **통째로
사라진다**(모든 엔드포인트가 모든 키를 갖게 된다). 절감액은 인용값 위의 추정이었고 대가는
코드로 확정 가능했다 ⇒ 기각. 같은 표에서 *"동시성 상한을 낮춘다"* 도 **사용자가 같은 문장에서
요구한 "누구나 사용할 수 있게"** 와 충돌해 기각됐다.

**How to apply:**
- 절감/성능 후보표에 **"기능·가용성을 깎는가"** 열을 **항상** 둔다. 사용자 요구가 두 절반으로
  되어 있으면(예: *"누구나 쓰게"* + *"돈은 아끼게"*) 그 열이 곧 판별자다.
- 후보를 적을 때 **직전 3개 절의 게이트를 전수 대조**한다 — 방금 세운 경계일수록 잊기 쉽다.
- **대가 0인 후보(설정 1회·운영 습관)를 먼저 찾아라.** 그것이 같은 문제를 닫으면 대가 있는
  후보는 **자동으로 기각**된다(§44에서 콘솔 정리 정책 1건이 함수 통합 논의를 통째로 없앴다).
