**"경로 X에서 기능 F가 안 된다"** 를 받으면, F의 **판정 로직**을 열기 전에 **F의 입력이 X까지 실제로 배달되는가**를 먼저 추적한다.

**Why:** §54(폴백에서 확인 데스크 전환 0회)에서 신고 문면은 *"폴백에서 계열 A 자동 전환이 안 된다"* 였고,
그대로 읽으면 계열 판정(`shouldAnnounceVerifyOffer`의 A 예외 = G264)을 고치게 된다. 그 함수는 **`callMode`를
입력으로 받지도 않았고** 완벽히 옳게 동작했다. 진범은 **5홉 떨어진 훅의 조기 반환 3개**
(`useRealtimeCall.start()`가 폴백으로 내려갈 때 `setCredentials`를 지나치지 않는다)였고, 그래서 게이트 입력이
영구 `undefined`였다. 판정 함수를 고쳤다면 **아무것도 안 고쳐지고 G264만 깨졌을 것**이다.

**How to apply:**
1. 주장을 두 개로 갈라 쓴다 — **(ㄱ) 판정 로직이 그 경로를 거부한다** / **(ㄴ) 판정 로직에 입력이 도달하지 않는다.**
   둘은 처방이 완전히 다르다. ([[feedback_inherited_impossibility_is_layered]]의 층 가르기와 같은 형태)
2. 입력의 **유일한 대입 지점**을 grep한다(`setX(`가 파일 전체에서 몇 줄인가). 한 줄뿐이고 성공 경로 전용이면
   그것이 답이다.
3. **경로별 입구를 전수로 표로 만든다**(E1~E5). "폴백"은 대개 입구가 하나가 아니다 — §54에서는 5개였고 그중
   **1개에서만** 상류 문서(§53.7)의 타임라인이 성립했다.
4. **같은 세션의 대조군**을 찾는다. §54에서는 통화 중 문자가 같은 폴백 세션에서 **정상 도착**했고, 그 비대칭
   (서버 오케스트레이션 vs 클라 오케스트레이션)이 결함의 정확한 모양을 알려 줬다.
5. ⛔ "서버가 그 값을 안 내려준다"고 단정하기 전에 **서버 허용목록을 열어라** — §54에서는 `"none"`(텍스트 폴백)이
   허용목록에 **명시**돼 있었고, 버리는 쪽이 클라였다. ([[feedback_absence_claims_check_the_sdk]])
