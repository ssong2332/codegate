방식(검출 수단·테스트 하네스)을 고를 때 **정상 경로가 되는가**만으로 순위를 정하지 말고, **오염 샘플을 같은 수단으로 잴 수 있는가**를 같은 표에서 함께 판정한다. 두 경로가 다른 수단이면 역검증은 정상 경로에 대한 증거가 아니다.

**Why:** T116(랜딩 렌더 층) 판정에서 실제로 겪었다. "컴포넌트를 직접 import해 렌더한다"가 신규 의존성 0건이라 1순위처럼 보였지만, 이 저장소의 완료 조건은 *"오염 샘플에서 새 검사가 실제로 실패하는 출력"* 이고 **오염은 테스트 코드 안에서만** 만들어야 한다(`callContinuity.test.ts:161-162` 관례). 직접 import는 디스크의 그 파일을 로드하므로 사본을 실을 수 없고, 우회 3안이 전부 다른 게이트(형제 파일 검사·상대 import 해석·"같은 수단" 규칙)에 걸렸다. ⇒ 1순위 후보가 프로브 중간 단계에서 무너질 수 있다는 것이 **설계 시점에** 드러났다.

**How to apply:** 프로브를 설계할 때 단계를 최소 3개로 쪼갠다 — ⓐ 정상 대상을 실을 수 있는가 → **ⓑ 오염 사본을 같은 수단으로 실을 수 있는가** → ⓒ 관측이 실제 값을 내는가. ⓑ를 독립 단계로 두지 않으면 "ⓐ 통과 = 채택"으로 착각한다. 그리고 강등표에 *"ⓐ ✅ · ⓑ ✗ ⇒ 다음 후보로 내려간다 · 절충(정상만 A, 오염만 B) 금지"* 행을 명시한다.
