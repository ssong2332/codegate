"늦게 도착한 무조건 쓰기를 조건부로 바꾸면 그 경쟁이 닫힌다"류 처방은 **덮어쓰기(지속 상태)** 만 닫는다. 피해 중 **서버가 그 상태를 다시 읽는 지점**(재검증 게이트)을 거치는 것만 막히고, **경쟁 창 안에서 이미 응답에 실려 클라로 내려간 값**은 상태 전이로 회수되지 않는다.

**Why:** codegate T181 OQ-A88(2026-10-02). §69.3 (5)가 `userAccess.ts:283` 조건화로 *"신고 뒤 클론 음성 재생 경쟁이 함께 닫힌다"* 고 적었고 User가 그 문장을 보고 승인했다. 코드를 다시 치니 닫히는 것은 `createRealtimeCall` 재검증 경로(통화 전체)뿐이었다. 동의 응답의 `openingAudioUrl`(클론 1문장)은 클라에 보관됐다가 실시간이 거부되면 폴백 분기에서 재생된다 — `:283`과 무관하게 원래 있던 갭이다. 같은 패스의 형제 슬롯 대조에서 같은 줄이 `deleted`(작성자 삭제)도 덮는다는 세 번째 경쟁이 새로 나왔다(상류는 2개만 들었다).

**How to apply:**
- 처방 문장의 피해를 **경로별 행**으로 편다: ① 서버가 그 상태를 다시 읽는 지점 ② 이미 응답·토큰·클라 저장소로 내려간 값 ③ 상태를 보지 않는 형제 콜러블. 조건화가 닫는 것은 ①뿐이다.
- ②가 남으면 원문은 두고 **"정정"** 으로 적는다. 닫는 형태(응답에서 빼기·거부)가 User 결정 문면 밖이면 OQ나 planner 인계로 넘긴다. 처방 커밋에 끼워 넣지 않는다.
- 그 줄의 쓰기와 경쟁하는 **모든 쓰기 지점**(신고·폐기·완료 등)을 표로 세운다. 상류가 든 목록에 하나가 더 있는 경우가 많다.
- 문면 편집 지점을 판정할 때도 같은 축을 쓴다. 서버 메시지는 **유일한 호출부의 catch가 버리면** 화면에 닿지 않는다(T181 `join/page.tsx:128-130`). 그러면 정본은 클라 분기이고, 서버 문자열은 편집 지점이 아니다.
