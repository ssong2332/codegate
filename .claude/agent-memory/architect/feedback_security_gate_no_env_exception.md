서버 보안 게이트에 환경 분기(`FUNCTIONS_EMULATOR` 등)를 두지 않는다. 개발 편의 때문에 게이트에 걸리는 쪽(예: 익명 dev 로그인)을 게이트를 정상 통과하는 방식(에뮬레이터 이메일 계정)으로 바꾼다.

**Why:** §68(2026-10-01, 익명 uid 스코프 게이트)에서 E1(서버 에뮬레이터 예외)을 검토해 보니, 라이브에서 익명을 켜기 전에 게이트를 실제로 돌려 볼 수 있는 곳은 에뮬레이터뿐이었다. 서버에 예외를 두면 그 유일한 검증 장소에서 게이트가 꺼져 사전 검증이 0회가 된다. 게다가 환경 분기 자체가 백도어 형태다.

**How to apply:**
- 권한·남용 게이트 설계에서 "에뮬레이터/개발 예외가 필요한가?"라는 질문이 나오면, 예외를 **클라 개발 도구 층**으로 내리는 선택지를 먼저 찾는다. 그러면 에뮬레이터가 게이트를 양방향으로 검증하는 장소가 된다.
- 허용/거부 전수 분류에서는 LLM 비용 행(createSession)만 보지 말고, **공격자가 자기 입장권(토큰·초대·세션)을 스스로 발급할 수 있는 행**(createChallenge)을 찾는다. 루프는 그 행에서 닫힌다.
- 거부 호출은 인자 검증보다 앞에 둔다. 그래야 빈 페이로드 프로브로 게이트 유무를 판별할 수 있다(있으면 거부, 없으면 invalid-argument — 비용 0).
- 활성화 순서와 롤백 순서는 대칭이 아니다. 켤 때는 게이트 배포가 먼저, 끌 때(롤백)는 기능 끄기가 먼저다.
