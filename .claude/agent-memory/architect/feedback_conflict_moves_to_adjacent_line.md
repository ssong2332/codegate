상류 패스가 지목한 "충돌 문장 집합"을 사용자 확정으로 철회할 때, **그 문장의 바로 앞뒤 줄을 반드시 읽고 충돌이 이동했는지 확인한다.** 철회로 끝내지 말 것.

**Why:** T125/§30 실측. §29가 (C) 조건부 치환 대상으로 지목한 4문장(*"확인하려 하면 압박한다"*)은 사용자가 *"한 번 막는 것을 설계로 받는다"* 고 확정하면서 대상에서 빠졌다. 그런데 **각 파일의 바로 다음 줄**에 지속 압박 절(*"한 번으로 끝내지 않고 계속 밀어붙인다"*)이 있었고, 그것이 채택의 **후반부**(*"재차 고집하면 넘긴다"*)와 새로 충돌했다. "채택으로 모순이 해소됐다"고 썼다면 거짓 보고가 됐을 것이다.

**How to apply:**
- 대상 집합을 철회할 때 결론은 3택이다: 완전 철회 / **대상 재지정** / **보류(측정 대기)**. 관측이 0건이면 **보류**가 정답이고, 발동 조건을 if/then 표로 못 박아 implementer에게 판단을 남기지 않는다.
- 이동한 충돌 줄이 **이전 사용자 확정으로 저작된 것**인지 확인한다(파일 주석·섹션 헤더에 사유가 적혀 있는 경우가 많다). 그렇다면 architect 단독 사안이 아니라 **사용자 판단 대기**로 올린다.
- 보고에는 *"충돌이 절반만 사라졌다"* 를 자기 고지로 남긴다.
