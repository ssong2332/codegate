"값이 화면에 안 나온다" 결함은 **그 값을 쓰는 곳부터 grep**한다. T181(2026-10-02): 챌린지 `completed`는 열거(§14.1)·재개 차단(§14.4)·슬롯 회수(§14.5)·동의 게이트 거절·클라 완료 문구에 **전부 있었는데 쓰는 코드는 0줄**이었고, 설계 문서도 전이 주체를 한 번도 정하지 않았다(§14.7.5 처리 단계가 `in_progress`에서 끝남). 클라 테스트는 서버가 만들지 않는 `completed` fixture 6개로 초록이었다.

**Why:** 소비자 층만 검증하면 생산자 부재는 영원히 초록이다. 그리고 생산 지점을 콜러블 하나에 두면 같은 상태로 가는 다른 경로(한도 종료 자동 종료 등)가 반드시 샌다 — 이 저장소는 리포트 트리거에서 같은 누락을 이미 한 번 겪었다(`roleplay/index.ts:402-409`).

**How to apply:**
- 상태 결함 신고 → ① 그 값의 **쓰기** 전수 grep ② 설계 문서에서 "누가 언제 쓰는가" 문장 grep — 둘 다 0이면 *구현 누락*이 아니라 *설계 공백*으로 판정하고 층별 표(전제한 것 / 쓰는 것)로 보인다.
- 전이 위치는 후보를 "모든 생산 경로를 받는가 · 실패/이탈 시 영구 미완료가 되는가 · 멱등인가"로 표 판정한다. 같은 필터를 이미 가진 트리거가 있으면 별도 트리거 신설보다 거기 얹는다(호출 2배 방지).
- 서버→클라 연결 증거는 **생산자 소스의 상수 리터럴을 소비자 테스트가 `readFileSync`로 읽어** 매퍼에 넣게 하고, 중간 통과 지점(pass-through)은 소스 스캔으로 고정한다 — 손으로 쓴 fixture는 증거가 아니다. 관련: [[order-audit-misses-early-return]], [[same-symbols-different-subjects]].
