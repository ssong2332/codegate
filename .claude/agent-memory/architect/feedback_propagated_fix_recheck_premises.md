**"같은 버그 클래스가 다른 경로에 남아 있다"** 는 인계를 받으면, 옮길 것은 **수정(diff)이 아니라 원 판정의 근거 문장**이다. 근거를 새 경로에서 **한 줄씩 다시 참/거짓으로 판정**하라. 하나라도 거짓이면 처방이 **뒤집히거나 형태가 달라진다**.

**Why:** §60(2026-09-07)에서 §56~§57의 "[계좌]" 마스킹 제거를 실시간 전사 경로로 옮기라는 인계를 받았다. 두 근거 중 **근거 1**(*"모델은 참가자 원문 PII를 입력으로 받은 적이 없다"*)이 실시간에서는 **거짓**이었다 — 브라우저가 음성 AI에 직결돼 모델이 원문 오디오를 그대로 듣고, 프롬프트는 오히려 참가자가 실 PII를 말하도록 유도한다. 그대로 복사했으면 **없던 프라이버시 노출 경로를 신설**했을 것이다. 근거는 코드 주석·설계 문서에 이미 문장으로 적혀 있는 경우가 많다(그 파일 헤더를 열면 나온다).

**How to apply:**
1. 원 수정 파일의 **헤더 주석/설계 절에서 "왜 그렇게 고쳤는가" 문장들을 추출**해 표로 만든다(근거 1, 근거 2, …).
2. 각 근거를 **새 경로의 코드로 다시 친다** — 특히 *"이 값은 이미 처리를 거쳤다"*·*"모델/서버가 X를 본 적이 없다"* 류는 **데이터 흐름이 다르면 곧바로 거짓**이 된다.
3. **판정을 "고친다/안 고친다" 2택으로 두지 말 것.** 근거 중 하나만 살아 있으면 보통 **범위를 좁힌 제3안**(예: 오탐을 낸 패턴 1개만 면제하고 나머지는 유지)이 성립한다 — [[feedback-inherited-impossibility-is-layered]].
4. ⭐ **클라가 보낸 값을 정규화하는 삼항의 기본 방향을 반드시 읽어라.** `x === "A" ? "A" : "B"` 는 *"정규화"* 처럼 읽히지만 실제 뜻은 ***"모르면 B"*** 다. 그 기본값이 **면제·완화 쪽**이면, 필드 누락 하나로 안전장치가 풀린다 — 악의가 없어도 발동한다. 면제를 도입하는 커밋은 **같은 커밋에서 방향을 반전**시켜야 한다.
5. 결론이 "현행 유지"라도 **DECISIONS 행으로 물질화**한다 — 안 그러면 다음 패스가 같은 신고를 *"아직 안 고친 버그"* 로 다시 연다([[feedback-verbal-confirmation-needs-a-decisions-row]]).
