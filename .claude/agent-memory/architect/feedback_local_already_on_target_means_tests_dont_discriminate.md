런타임·플랫폼 버전 상향을 판정할 때는 먼저 **로컬 실행 환경이 이미 어느 버전인지**를 확인하라. 로컬이 이미 목표 버전이면 로컬 build/test/emulator는 상향 전에도 그 버전에서 돌고 있었으므로 **전/후 수치 동일은 "무회귀"일 뿐 "상향 검증"이 아니다.** 판별 증거는 배포 경고 소멸 · 배포 후 런타임 목록 · 라이브 스모크뿐이다.

**Why:** T147(2026-09-30)에서 인계된 완료 조건이 "테스트 수 전/후"를 핵심 증거로 두었지만 로컬 Node가 이미 22.14였다 — 그 조건만으로 완료를 보고하면 근거 없는 성공 보고가 된다. 같은 사실이 목표 버전 선택도 갈랐다: 로컬 = 배포가 환경 변경 없이 성립하는 버전(22)이 폐기일이 더 긴 버전(24)을 이겼다.

**How to apply:**
- 판정 초반에 "로컬이 무엇으로 도는가"를 저장소 안 증거(스크립트 주석·실측 기록)로 찾는다.
- 완료 증거표에 증거별 **판별력 열**을 두고 "무회귀만"을 명시한다.
- 동시에 두 변경(런타임+SDK)이 오면, 검증 층이 다르면(배포 층 vs 로컬 게이트) **배포까지 분리**하라 — 커밋 분리만으로는 라이브 이상 귀속이 안 된다.
