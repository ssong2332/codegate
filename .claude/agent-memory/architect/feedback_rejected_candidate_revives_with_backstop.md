기각된 설계 후보를 다시 볼 때는 **기각 사유를 표로 펼쳐 한 행씩 오늘 트리에서 재판정**한다. 사유가 전부 죽지 않아도 되고, **마지막에 남는 것이 "그 방식은 X를 *보장*하지 못한다" 하나면 후보는 죽은 것이 아니다** — 보장은 기존 경로를 **백스톱(천장)** 으로 남겨서 사면 되고, 그러면 새 방식은 "더 좋을 때만 이기는" 층이 된다.

**Why:** §57에서 ADR-0007이 기각한 Gemini Live function calling을 4사유로 펼쳤더니 ①은 줄번호가 밀렸고 잠금의 *취지*(클라의 임의 주입 차단)를 서버 선언이 어기지 않았으며, ②는 범위를 한 프로바이더로 좁히면 발동하지 않았고, ③은 미확인(프로브), ④ *"도착을 보장 못 한다"* 만 살아남았다. ④는 **하한(게이트)+모델 시점+천장(기존 카운터)** 하이브리드로 그 자리에서 사라졌다. 사유를 뭉뚱그려 *"ADR이 이미 기각했다"* 로 닫았으면 유일한 해를 버렸을 것이다.

**How to apply:**
- 기각 사유는 **원문에서 그대로 뽑아 행으로** 만든다. 인용된 파일:줄은 **밀려 있다고 가정**하고 다시 grep한다(§57 ①: `:122-123` → `:187-188`).
- 각 행을 **약화 / 유효 / 미확인(프로브)** 셋으로만 판정한다. "유효"가 하나라도 남으면 **단독 채택은 기각**이라고 명시적으로 적는다.
- 남은 사유가 **보장·결정론·커버리지 부재** 계열이면 **백스톱 설계**를 시도한다: 새 경로는 상한 전에만 이기고, 상한을 넘으면 기존 경로가 그대로 돈다 ⇒ 기존 테스트·AC가 **무약화 0**으로 살아남는다.
- ⛔ 원 ADR은 수정하지 않는다. 새 절에 *"그 시점에는 옳았고 지금도 단독 채택에는 옳다 — 달라진 것은 조건이 처음 제시됐다는 것"* 으로 적고, 채택 시 **신규 ADR**을 낸다.
- ⛔ 잠금을 푸는 후보라면 **잠금을 지키던 게이트가 문면보다 넓은지** 먼저 본다([[feedback_tripwire_not_contract]]) — `tools`는 문자열 존재만 단언해 도구를 넣어도 초록이었다.
