T104(상황별 인앱 가짜 랜딩 4종)에서 얻은, 코드만 읽어서는 안 나오는 판단들.

**Why:** 이 태스크는 "게이트를 삭제하지 말고 판정 키를 옮겨라"라는 드문 형태였고(ADR-0012),
착수 순서 자체가 하드 게이트였다. 같은 형태가 또 나올 때 같은 고민을 반복하지 않기 위해.

**How to apply:** codegate에서 기존 안전 단언의 스코프를 좁히는 작업을 받을 때.

## 1. "①게이트 → ②정밀화 같은 커밋 → ③콘텐츠" 순서에서 G-B만 ③으로 밀었다
신규 게이트 5건(G-A~G-E) 중 **G-B(양방향 참조 정합)만** ①에 못 넣었다. G-B ①방향은
"`IN_CALL_SMS.fakeLandingId`가 카탈로그에 존재할 것"인데, 그 참조 대상이 ③에서 들어오므로
①커밋에서 단언하면 **중간 커밋이 빨개진다**(= "테스트 통과 없는 커밋 금지" 위반).

판정 근거: 순서 강제의 목적은 *"정밀화가 여는 구멍"*(M2: app-install이 통화 경로로 열림)이고
그건 G-A·R6·정밀화된 G55/channel이 ①에서 닫는다. G-B가 닫는 M5(통화 경로 랜딩이 아무
게이트도 안 탐)는 **base main에 이미 열려 있던 구멍**이라 한 커밋 미룬다고 새로 열리지 않는다.
→ 커밋 메시지에 이 구분을 명시했다. 다음에 같은 상황이면 같은 기준으로 나눠라:
**"이번 변경이 여는 구멍"은 ①, "원래 열려 있던 구멍"은 ③과 함께**.

## 2. `PUBLIC_SCENARIOS[x].channel`은 옵셔널이고 음성 시나리오는 필드를 아예 안 갖는다
`channel === "voice"`로 세면 **0건**이 나온다(publicMeta.ts:29 `channel?: Channel`).
음성 판정은 항상 `channel !== "messenger"`로 써야 한다. 이 함정에 실제로 한 번 걸렸다.

## 3. 격리 에뮬레이터 REST 검증 레시피(포트가 3중으로 점유돼 있던 날)
- 기본 포트(9099/5001/8080)뿐 아니라 9599/8580/5501까지 다른 에이전트가 잡고 있었다.
  `netstat -ano | grep LISTENING`으로 **범위 전체를 먼저 훑고** 비어 있는 대역(9711/5711/8711/4711)을 골랐다.
- functions 에뮬레이터는 `functions/.env`가 없으면 **`LLM_PROVIDER`를 대화형으로 묻고 멈춘다**
  (백그라운드 실행 시 그냥 매달려 있는 것처럼 보인다). 새 워크트리에서는 루트 `.env`와
  `functions/.env`를 **둘 다** 메인 저장소에서 복사해야 한다(둘 다 gitignore).
- `createSession`은 AC-017 서버측 동의 게이트가 있어 `users/{uid}/consents`에 `granted:true`
  문서가 **먼저** 있어야 한다. Firestore REST로 만들 때 **Authorization: Bearer idToken을 안 붙이면
  403**이다(에뮬레이터도 rules를 적용한다).
- `sendMessage` 응답의 통화 중 문자 필드 이름은 `deliveredSmsId`가 아니라 **`sms: { smsId }`** 다.

## 4. 드리프트 파서를 "첫 블록만" → "항목 단위 순회"로 바꿀 때의 경계
카탈로그 소스 텍스트를 파싱할 때 마지막 항목 블록의 끝을 파일 끝으로 잡으면 **선언 뒤의 함수·주석까지
빨아들인다.** `export const MOCK_SCREENS` 위치를 앵커로 잡고, 모든 `landingId:` 매치가 그 앵커보다
앞에 있는지 단언하면 "항목을 선언 뒤에 추가" 하는 우회도 함께 막힌다.
그리고 `momentTactic`·`correctAction`은 **화면에 있으면 오히려 잘못**이다(리포트용) — 렌더 필드와
리포트 필드를 나눠 등록부로 만들고 등록되지 않은 속성이 나오면 실패시켰다.

## 5. 무해화 — 환급/통관 문안에서 실제로 위험했던 지점
`mockSurface` 프로파일만 `realInstitutionName`을 켠다. 국세청·관세청·우체국을 피하는 대신
**문자 본문(`inCallSms.ts`)이 이미 쓰고 있던 가상 발신 주체**("○○캐피탈", "국제통관지원센터")를
그대로 재사용했다 — 새 가상 이름을 지어내는 것보다 미끼-화면 일관성이 좋고 검토 부담도 없다.
`correctAction`만 `correctiveGuidance` 프로파일이라 112·1332를 쓸 수 있다(다른 필드는 못 쓴다).
