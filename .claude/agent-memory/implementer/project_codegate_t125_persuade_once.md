## 1. ⭐ architect **초안**과 오케스트레이터 **금지어**가 충돌하면 — 요건이 정본, 초안은 좁힌다

§30.2.5 초안은 *"**한 차례** 만류하되"* 를 썼고 자기 점검표에 *"숫자·서수 0개 ✅"* 라고 적었다.
그런데 오케스트레이터 지시는 ⛔ *"**한 번** 같은 카운터 표현 금지"* 였다. **둘 다 따를 수 없다.**

판정: **§30.2.5 헤더가 *"요건이 정본이고 이 초안은 예시다"* 라고 명시**했으므로 요건(F11)을 따르고
초안에서 *"한 차례"* 를 **뺐다**. F11 요건 원문 *"먼저 …한다. 그러고도 상대가 **다시** …하면"* 형태는
카운터 어휘 없이도 완전히 성립한다.

**How to apply:** 설계 문서가 초안/예시라고 자백한 문자열은 **그대로 베끼지 마라.** 상위 요건과
오케스트레이터 금지어의 **교집합**으로 다시 쓰고, 무엇을 왜 좁혔는지 보고에 적어라.
⚠️ 이번엔 초안을 그대로 썼으면 **금지어를 그대로 커밋**할 뻔했다.

## 2. ⭐⭐ "이 변경이 X 조건에서 **바이트 동일**하다"를 증명하는 레시피 (재사용 가치 높음)

역검증(b)의 기존 형태는 *"꺼진 조립에 마커가 없다"* 였다 — 그건 **부재 증명이지 무변경 증명이 아니다.**
실제 무변경을 재려면 base와 변경본의 **산출물 해시를 비교**해야 한다.

```
1. 스크래치패드에 dump 스크립트(.mjs) — functions/lib/*.js를 pathToFileURL로 절대경로 동적 import,
   모든 조합을 정렬된 순서로 조립 → 합친 문자열의 sha256 + 바이트수 출력
2. (변경본) npm --prefix functions run build → node dump.mjs → 해시 A
3. cp 대상소스 → 스크래치패드 백업;  git checkout <base> -- 대상소스;  build;  dump → 해시 B
4. cp 백업 → 대상소스 (복원);  build
5. A === B 이면 무변경 증명 완료
```

⚠️ **`git stash`를 쓰지 마라** — 이 저장소에서 줄끝을 바꾼 전례가 있다([[codegate-t108-ast-source-scan]]).
`cp` 백업 + `git checkout <base> -- <path>` 가 안전하다.
⚠️ 스크립트는 **스크래치패드에 둔다**(워크트리에 두면 커밋에 섞이거나 tsc가 집는다).
⚠️ 이 레시피는 커밋된 테스트가 아니라 **일회성 증거**다 — 보고/PR에 해시를 적어 남긴다.

## 3. 깨지는 게이트 수는 **소스를 먼저 고치고 돌려서** 확정한다

지시가 *"몇 건이 깨지는지 먼저 실행으로 확정할 것"* 이었다. 순서:
**① 소스만 교체 → ② 테스트 실행(3 fail 확정) → ③ 그제서야 게이트 갱신.**
게이트를 먼저 고치면 *"원래 몇 건이 걸렸는가"* 라는 숫자가 **영영 사라진다.**

이번 실측: F1 리터럴 단언 때문에 **3건**(`[T125 전수]`·`[T125/역검증(a)]`·`[T125] 선언은 기존 4개 항목…`).
`역검증(b)`는 **부재를 재는 테스트라 안 깨졌다** — 방향이 반대인 게이트는 문면 교체에 면역이다.

## 4. 라이브 예산이 대조군에 못 미치면 — **돌리지 말고 스코프 컷으로 보고**

일일 20건 중 18건 소모, 필요 세트는 9건. **2건으로는 대조군조차 못 만든다** ⇒ 0건 실시.
보고에서 이것을 **결함이 아니라 예산 제약**으로 분류하고, PR·Tasks.md Status·커밋 메시지
**세 곳 모두**에 *"효과 주장 0건"* 을 적었다([[codegate-t125-verify-scope]] 1의 형식 계승).

**Why:** 대조군 없는 회차는 G121 정면 위반이고, 합격 회차 하나가 나오면 **오보의 씨앗**이 된다.

## 5. 재발 확인 — `npm install`이 `functions/package.json`을 고친다

새 워크트리에서 루트+functions install 후 `functions/package.json`에
`"fraud-vaccine-web": "file:.."` 가 **자동 추가**됐다(+ lock). [[codegate-t119-offer-gate-values]] 기록대로였고
[[codegate-t125-verify-scope]] 5의 *"이번엔 안 났다"* 와는 갈렸다 ⇒ **매번 `git status`로 확인하고
`git checkout --` 로 되돌린 뒤 착수**하라. 항상 나지도, 안 나지도 않는다.

## 6. 이 태스크의 설계 프레이밍 (다음 사람이 오독하기 쉬운 지점)

⛔ ***"저지를 없앤다"* 가 아니다.** 사용자가 **목표 자체를 철회**했고 이제 **1회 만류가 설계**다.
§28·§29는 *"저지 제거"* 를 목표로 쓰였고 **폐기되지 않았다 — 전제가 바뀐 것**이라 §30이 위에 얹혔다.
⇒ 저장소의 §28/§29 문면을 읽고 *"아직도 저지를 없애야 하는구나"* 로 읽으면 **정반대 구현**이 나온다.
그리고 충돌은 **절반만** 사라졌다(지속 압박 절과는 여전히 충돌, (C)는 관측 후 사용자 판단).
