T86(`feat/T86-harmlessness-guards`, 2026-07-26)에서 코드·커밋에 안 남는 판단만 적는다.

## 1. 이 저장소에서 "금지어 전역 적용"은 **제품 요구를 위반한다** — 반드시 프로파일 표로 쪼갠다
전역 블록리스트를 만들면 곧바로 세 곳에서 정당한 콘텐츠를 때린다:
- `PUBLIC_SCENARIOS`/프롬프트의 **사칭 대상** 기관명 — PRD가 시나리오 제목으로 못박았다("기관 사칭(검찰·금융감독원)", "국세청 환급금 빙자").
- 리포트 대처 문구의 **신고처** — AC-071이 112·1332를 **명시 요구**한다(`verifyIntercept.ts:19` 주석이 이미 경고하고 있었다).
- 메신저 시나리오 제목의 **"(카카오톡)"** — OQ-18 accepted risk. 그래서 앱명 목록에 "카카오"류를 넣으면 안 되고 "카카오뱅크"만 넣는다.

**How to apply:** 금지 패턴을 넓힐 때 목록이 아니라 `SCAN_PROFILES` 같은 **표면×패턴군 판정표**를 먼저 쓰고, 빠진 칸마다 "왜 빼는가"를 근거(AC 번호)와 함께 적는다. 표 없이 목록만 넓히면 반드시 되돌리게 된다.

## 2. JS `\b`는 ASCII 단어 경계라 **한글 문맥 금지어가 조용히 죽는다**
기존 `mockScreens.test.ts`의 `/\b앱\s*스토어\b/`·`/\bplay\s*스토어\b/`는 한글 텍스트에서 사실상 매치되지 않는다(앞뒤가 모두 비-word 문자면 경계가 성립하지 않는다). 통과하고 있어서 아무도 몰랐다. `\b`를 떼자마자 그동안 안 보이던 콘텐츠 2곳이 즉시 검출됐다.
**How to apply:** 한글 금지어·한영 혼용 패턴에 `\b`를 쓰지 마라. 기존 패턴을 물려받을 때는 **일부러 오염 샘플을 넣어 실제로 잡히는지** 먼저 확인한다(패턴이 통과한다 ≠ 패턴이 작동한다).

## 3. 금지어가 **금지형 지시 안에서** 등장하는 것은 위반이 아니다 — 다만 값과 이름을 갈라야 한다
프롬프트에 *"실존 앱 이름·앱스토어를 절대 말하지 않는다"* 가 있는 것은 무해화를 **강화**하는 문장이다. 이 저장소는 이미 그 판정을 두 번 했다(`verifyIntercept.test.ts` `[OQ-38/D-6]`, `scenarios.test.ts` `[AC-071/OQ-38]` — 둘 다 "등장 자체가 아니라 금지형인지"를 본다).
⚠️ 예외를 **패턴군 단위로 주면 안 된다.** 같은 `storeAndInstall` 군 안에도 `앱 스토어`(이름, 예외 가능)와 `https://`·`.apk`·`play.google`(값, 예외 불가 — 금지형 문장 안에 있어도 문자열이 산출물에 남는다)이 섞여 있다. **규칙 단위 플래그**로 쪼개고, "긍정형은 여전히 잡힌다"를 역검증으로 함께 고정한다.

## 4. 우회 방지 게이트는 3겹을 다 쓸 수 있다 — 각각 잡는 실패 양식이 다르다
| 겹 | 구현 | 잡는 것 | 실사격 결과 |
|---|---|---|---|
| 타입 | `Record<keyof Item, FieldPolicy>` | 항목 타입에 **텍스트 필드 추가** | `TS2741`로 컴파일 차단 |
| 런타임 | 카탈로그 키·런타임 필드 `deepEqual` | 항목/시나리오 추가, 옵셔널 필드 등장 | 테스트 실패 |
| 파일 | `readdirSync` 등록부 `deepEqual` | **새 카탈로그·새 화면 파일** | 테스트 실패 |
세 번째가 없으면 "새 파일 하나 만들어서 그 안에만 콘텐츠를 넣는" 우회가 열린다. 선례는 `mockScreenCopy.test.ts`의 형제 파일 검사인데 그건 이름 규칙(`/landing|install|mockup/`)에 걸리는 것만 봐서 좁았다.

## 5. 테스트 헬퍼는 `__tests__/`에 두면 러너에 안 잡힌다
`functions/package.json`의 글롭이 `lib/**/__tests__/*.test.js`라 `__tests__/harmlessnessPatterns.ts`는 import 전용 모듈이 된다(별도 `testing/` 디렉터리를 만들 필요 없음). 루트(`src/`)에서는 **import로 공유할 수 없으므로**(별도 TS 빌드 루트) 서버 정본 파일을 **소스 텍스트로 읽어 배열 리터럴을 파싱**한다 — `mockScreenCopy.test.ts`가 카탈로그 문구에 쓰던 기법 그대로다. 루트 테스트는 `package.json`의 파일 목록에 **손으로 등재**해야 돈다.

## 6. 이번에도 워크트리가 작업 중에 다른 브랜치로 바뀌었다
지시는 "T85 미병합이니 `origin/feat/T85-difficulty-levers`에서 분기하라"였고 그대로 했는데, 작업 중 다른 에이전트가 `main`을 체크아웃했고 그 사이 **T85가 main에 병합**됐다. 결과적으로 커밋이 `main`에 떨어졌다(직접 커밋 금지 위반).
**복구 순서(파일 churn 0)**: `git branch -f <feat> <내커밋>` → `git checkout <feat>`(트리 내용 동일이라 파일이 안 움직인다) → `git branch -f main origin/main`. 그 다음 **베이스가 바뀌었으므로 전체 검증을 다시 돌린다.**
**How to apply:** 커밋 직후 `git branch --show-current`와 커밋 출력의 `[branch]`를 반드시 확인한다. 긴 태스크에서는 중간에도 한 번 본다.
