`SCENARIO_AXES[].exitBlock`(손으로 유지되는 요약)이 `*.prompt.ts`의 `weakenedTactics`(전량)보다
좁아 9/13행 언더카운트였고, 그중 3행은 `D0_none`("수법 없음")이라 **적극적 오보**였다.
표가 콘텐츠를 따라가는 방향으로만 고치고, 재발 방지 게이트를 함께 넣었다.

**Why:** 이 표의 실패 양식은 "근거 없이 손으로 유지된 것"이다 — 정정만 하면 같은 드리프트가
다시 난다. 그래서 정정 + 게이트가 한 세트여야 했다.

**How to apply:**

1. ⭐ **요약표↔원본 드리프트 게이트는 3단으로 짠다.** ① 패턴 규칙표(라벨→값) ② 양방향
   `deepEqual`(누락 **과** 허위 추가) ③ **의심 어휘 백스톱** — 이탈 차단처럼 읽히는 어휘를 가진
   라벨이 규칙표에도 예외 목록에도 없으면 실패시킨다. ③이 없으면 새 라벨이 조용히 통과하는
   **거짓 OK** 경로가 남는다([[false-reassurance-over-precision]]). 예외 목록의 각 항목엔
   *"왜 D가 아닌가"* 를 적어야 판정이 재현된다.
2. ⭐ **대조 단위는 라벨부(첫 `—` 앞)다.** 설명부까지 매칭하면 오탐이 난다 — 예: "다급함 조성 —
   ... **시간 압박**만 준다"는 설명에 D1 어휘가 들어 있다. 문서의 architect 실측도 라벨만 인용했다.
3. ⭐ **문서의 실측표를 재현할 때 줄번호가 밀린 것은 불일치가 아니다.** §17.1.1(2026-07-26) 대비
   판정은 13/13 동일했지만 인용 줄번호는 T85·T91·T92 콘텐츠 증분 탓에 최대 +17줄 밀려 있었다.
   **판정(어느 행이 어느 값을 누락했는가)이 같으면 진행하고, 줄번호 드리프트는 architect 인계로
   보고**한다. 라벨 문자열 자체가 사라졌다면 그때가 진짜 중단 사유다.
4. **게이트를 테스트 파일에만 둔 이유**: 축 표의 소비처는 설계상 "테스트 단언 + 리포트 스크립트"
   2곳뿐이고(§15.10.3), `src/`에 파생 모듈을 만들면 세 번째 런타임 소비처가 생겨 DECISIONS #43
   ("L3는 축 표를 읽지 않는다")을 잠식한다.
5. **역검증 3종을 한 커밋 메시지에 넣는 것이 이 저장소 관례**다. 이번엔 ① 언더카운트 재현
   ② 허위 추가 ③ 백스톱(예외 목록에서 항목 1개 제거) — ③처럼 **콘텐츠를 건드리지 않고 게이트
   자신을 훼손하는 프로브**가 안전하다(프롬프트 파일 임시 편집은 위험).
6. 이 워크트리는 `node_modules`가 **루트·functions 둘 다 없어** 먼저 설치해야 했다.
   `cd functions && npm install` / 루트 `npm install` 둘 다 `package.json` 오염 0건(실측).
