**T136 = "리포트가 참가자에게 사실이 아닌 것을 말한다" 계열 세 번째**(D-61 · §38 다음). 해소는
`docs/Architecture.md` §42.6 **B(데이터 층 합집합)** 만, A(문면)는 ux-design.

**Why:** 이 저장소는 리포트 정직성을 반복 투자 축으로 삼고 있고, 그 계열은 매번 *"모르는 것"을
"없는 것"으로 렌더"* 하는 같은 형태로 재발한다.

**How to apply:**

1. ⭐⭐ **설계 절 안에서 규칙끼리 당길 때 — 문서 밖으로 나가지 말고 "둘 다 만족하는 3안"을 찾아라.**
   §42.6 **B-1**("입력은 **최종** `deceivedMoments`다" — T83 덮어쓰기 때문)과 **B-4 / if-then 8**
   ("합집합 입력은 실제 승격분만" · "승격 0건이면 **항등**")은 그대로 읽으면 충돌한다(전자를 문자
   그대로 하면 대화 추정 폴백 라벨 `"약화된 사기 수법"`·T83 라벨까지 목록에 들어가 항등이 깨진다).
   ⇒ 해소: **최종 배열을 입력으로 받되, 카탈로그 `momentTactic` 소속인 항목만 고른다.** 승격 순간의
   수법은 정의상 카탈로그 저작 상수(`buildLandingSubmitMoment`가 유일 조립 지점)이므로 이 필터가
   "승격분만"과 등가이고, 입력은 여전히 최종 배열이라 B-1도 지킨다. **architect 재소집 없이 닫혔다.**
2. **P-1(전제 검증)이 "접근 불가"로 끝나는 것은 정상 경로다.** 기동 중인 공유 에뮬레이터의
   `reports`·`sessions`를 owner 토큰 REST로 조회해 **둘 다 0건**임을 보이면 if/then 1(→P-2 직행)이
   적용되고, **착수 중지 조건(if/then 2)은 발동하지 않는다**(관측 자체가 없으므로). ⛔ 이때
   *"재현 못 해서 원인 미상"* 으로 멈추지 말 것 — F1은 코드만으로 확정돼 있었다.
   - 프로젝트 id는 `.firebaserc`가 아니라 **`http://127.0.0.1:4000/api/config`** 에서 나온다(여기선
     `demo-test`). Firestore REST는 rules를 타므로 **`Authorization: Bearer owner`** 로 우회한다.
3. ⭐ **역검증은 3층으로 갈렸고 1층이 컴파일러였다.** 리포트 필드를 원복(`tacticsUsed: analysis.
   tacticsUsed`)하면 테스트가 아니라 **TS6133('declared but never read')로 빌드가 먼저 죽는다** —
   테스트 출력이 아예 안 나온다. 그래서 *"소스 게이트가 실제로 무는가"* 를 보이려면 **컴파일되는
   위반**(합집합 입력을 `analysis.deceivedMoments`로 교체 = B-1 위반)을 따로 만들어야 했다.
   [[codegate-t82-axis-model]]의 "TS6133이 3겹째 게이트"와 같은 현상이 **이번엔 1겹째**로 나왔다.
4. **`generateReportCore`를 부르는 단위 테스트가 이 저장소에 0건이다**(Firestore 의존). ⇒ 합집합
   **배선**은 관측 불가 지점이라 `readFileSync` 소스 게이트로 고정했다
   ([[feedback-unobservable-behavior-gates]] 적용). 주석 스트립(`codeOnly`)은 필수 —
   자기 설명 주석이 금지 문자열에 걸린다.
5. **보고에서 지우면 안 되는 것(G220)**: 관찰 1회 · planner/architect/implementer 재현 0건 ·
   (ㄴ) 기각 아님 · (ㄷ) 미확정 · **B는 부분 해소**(고친 것은 "수법 집계"가 아니라 "한 리포트 안의
   두 서술이 어긋나는 것").
