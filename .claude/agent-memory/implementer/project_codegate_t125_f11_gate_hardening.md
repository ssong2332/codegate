## 1. ⭐ 열거형(화이트리스트) 게이트는 **열거에 없는 표현으로 뚫린다** — 형태로 바꿔라

`[T125/F11]`은 고정 15개 토큰 리스트였고 QA가 *"**세 번째** 확인 요구부터는…"* 으로
**5건 전원 통과**시켰다. `"세 번째"`·`"두 차례"`·`"재차"`·`"거듭"`이 전부 리스트 밖이었다.

**How to apply:** 금지어 게이트를 새로 쓸 때 **리스트를 만들지 마라.** 리스트는 "지금 생각난 것"의
스냅샷이다. 형태(정규식 유형표)로 쓰고, **리스트는 회귀 방지용 하위 집합 단언**으로만 남겨라
(이번엔 `LEGACY_TOKENS` 15개가 새 검출기에 전부 잡히는지 기계로 고정 = 약화 없음 증명).

## 2. ⭐⭐ 한국어 수사는 **고유어 / 한자어 두 계열**이다 — 한쪽만 담으면 다시 뚫린다

QA가 제안한 수정안 `/[일이삼사오육칠팔구십]+\s*번째|…/`는 **한자어만** 담았고,
**정작 QA 자신이 뚫은 고유어 `"세 번째"`를 못 잡는다.** 제안을 그대로 베꼈으면 재우회였다.

- 고유어: 한·두·세·서·석·네·너·넉·첫·다섯…·스무·몇 (+ 서수 `-째`: 첫째·셋째)
- 한자어: 일·이·삼·사·오·육·칠·팔·구·십
- 단위: 번째·차례·회차·회·번·턴 / 숫자: `[0-9０-９]` **전각 포함**

**How to apply:** 리뷰어·QA가 준 정규식은 **반드시 그 사람이 뚫은 입력으로 먼저 돌려 봐라.**
제안자가 자기 우회를 못 잡는 경우가 실제로 있었다.

## 3. ⚠️ 오탐 방지선은 **경계 lookbehind/lookahead**다 (실측)

`(?<![가-힣])(?:일|이|…)\s*(?:번|회|턴)(?![가-힣])` 에서 경계를 빼면
배포 문면의 *"두 사람**이 번**갈아 말하거나"* 가 한자어 `이`+`번`으로 **오탐**된다.
같은 이유로 `(?![가-힣])`가 *"**1인**칭"* 을 `숫자+단위`에서 배제한다.

⇒ **맨 숫자 금지(`[0-9]`)는 블록 전체로 넓히지 못한다** — 4항에 *"1인칭"* 이 실재한다.
넓힌 정규식은 블록 전체, 맨 숫자는 선언 두 줄만 — **대상 코퍼스를 규칙마다 다르게 잡는 것이 정답**이었다.

## 4. ⛔ 검출기를 `weakenedTactics`(수법 목록)에 걸지 마라

`institutional-impersonation`의 수법에 *"불이익을 **재차** 암시한다"* 가 실재한다.
**저작된 수법 문면**이지 F11이 금지하는 **지시 조건**이 아니다. 지시문 게이트를 콘텐츠에 걸면
정상 콘텐츠를 물고, 이 저장소는 **오탐이 게이트를 통째로 삭제하게 만든 전례(§24.4)** 가 있다.

## 5. ⚠️ 함정 — 오염 주입 스크립트의 **원복이 내 테스트 샘플까지 되돌렸다**

역검증용으로 QA 오염 문구를 소스+테스트 리터럴에 문자열 치환으로 주입했다. 되돌릴 때
**내가 새로 추가한 `MUST_CATCH` 샘플에도 같은 문구가 들어 있어** 치환이 2곳에서 일어나
샘플이 조용히 오염 전 문면으로 바뀌었다(`git diff --stat`은 정상처럼 보였다).

**How to apply:** 주입/원복은 **반드시 `cp` 백업 + `sha256sum` 일치 확인**으로 닫아라.
문자열 치환 원복은 "치환 건수"를 출력시키고 **주입 때와 건수가 같은지** 보면 즉시 잡힌다
(주입 1곳 / 원복 2곳 → 사고). `git stash`는 여전히 금지(줄끝 변경 전례).

## 6. 이 태스크의 프레이밍 — **현재 결함 수정이 아니다**

배포된 `VERIFY_INTERCEPT_RULE`은 이미 카운터 0개였다. 산출물은 **게이트만** 바뀌고
`promptAssembly.ts` · `*.prompt.ts` **diff 0줄**이 정상이다. 보고에서 이것을 먼저 말하지 않으면
"버그를 고쳤다"로 오독된다.
