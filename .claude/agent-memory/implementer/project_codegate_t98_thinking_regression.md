`fix/T98-regression-thinking-config`(2026-07-27)에서 얻은, 코드만 읽어서는 안 나오는 것들.

## 1. ⚠️ 공유 에뮬레이터는 **다른 워크트리의 `lib`을 절대 집지 않는다**
오케스트레이터가 "빌드 후 에뮬레이터가 새 lib을 집는지 확인하라"고 지시했지만, 떠 있던
에뮬레이터는 `C:\codegate`(메인 트리)에서 기동된 것이었고 내 수정은 워크트리에 있었다 —
빌드를 몇 번 하든 반영될 수 없는 **구조적 불가능**이지 타이밍 문제가 아니다.

**How to apply:** 워크트리 에이전트가 라이브 증거를 요구받으면, 공유 에뮬레이터를 재기동하려
하지 말고 **워크트리에서 격리 인스턴스를 띄워라**(포트만 겹치지 않으면 공유분과 무해하게 공존).
레시피는 [[codegate-t104-situational-landings]] §3 + 이 파일 §4.

## 2. 죽은 안전장치를 "지운다 vs 남긴다" 판정 기준
`isThinkingConfigRejected()`는 에러 **메시지 문자열**(`/thinking/i`)로 판정했는데, 실제 400
메시지는 `"Request contains an invalid argument."` 라 한 번도 발동하지 않았다.
→ 판정 기준: **"실제 발생한 케이스를 못 잡은 게이트"는 남기지 말고 지운다.** 남기면 다음 사람이
"방어되고 있다"고 오판한다(T86의 죽은 게이트 교훈과 같은 방향). 대신 삭제 근거·재도입 조건을
주석에 남겨 git 이력 없이도 읽히게 한다.

**Why:** 벤더 에러 메시지는 계약이 아니다. 에러 문자열 매칭으로 폴백을 거는 설계 자체가 함정.

## 3. `-latest` 별칭 금지 — 이 저장소는 실제로 이걸로 라이브가 죽었다
`gemini-flash-latest`가 아무 신호 없이 `gemini-3.6-flash`로 재매핑되면서 설정이 거부됐다.
코드는 그대로인데 상대가 바뀌는 "낡은 사본"의 역방향 사고. 텍스트 경로는 이제 고정 버전이다.
참고: 실시간 경로(`realtime/geminiProvider.ts:23`)는 원래부터 고정 버전이라 같은 위험이 없다.
⚠️ `gemini-2.5-flash`는 이 계정에서 404("no longer available to new users") — 되돌릴 수 없다.

## 4. Gemini 예산 제약 아래서 증거 4종을 **1회 호출**로 묶는 법
무료 티어 일 20건/분 5건이라 재시도 여유가 없다. `createSession` 1회로:
`result.isMock`(⚠️ `message.degraded`가 아니다) · 에뮬레이터 로그의 `"Mock으로 강등"` 0건 ·
`Finished "..." in N ms`(컨테이너 콜드스타트가 빠진 진짜 실행시간) · 오프닝 대사 원문을 한 번에 얻는다.
실패 지점(로그인·동의 문서 write)은 **LLM 호출보다 앞**이라 스크립트가 거기서 죽으면 예산은 안 탄다 —
검증 스크립트는 항상 이 순서로 짜라.

## 5. 낭독 여부 판정은 "인용구 개수"만으로 하면 오독한다
`weakenedTactics`의 `'...'` 인용구 19개 중 실 LLM 대사에도 1개(`수사관`)가 들어 있었지만,
그건 직함이 문장에 자연스럽게 쓰인 것이다. 같은 시나리오의 Mock 출력은
`"여보세요...? 수사관, 금융감독원."` — **인용구를 이어 붙인 형태 자체**가 낭독의 표식이다.
→ 개수뿐 아니라 **문장 구조**를 함께 보고, Mock 출력을 로컬에서 만들어(비용 0) 나란히 대조하라.
