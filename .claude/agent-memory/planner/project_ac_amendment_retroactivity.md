**AC 문면이 좁다는 것이 드러나도 제자리 수정하지 말고 "확정 시점의 다음 미사용 번호로 신설"을 기본안으로 권고하고, 최종 결정은 사용자 확정으로 넘긴다.**

**Why:** 소급 영향을 두 층으로 나눠 봐야 한다 — ① **실질 판정**(구현물이 강화된 문면도 만족하는가)과 ② **제출된 증거**(그 문면을 증명하는 출력이 산출물에 있는가). ①이 안 뒤집혀도 ②는 뒤집힌다: T104는 AC-078 (b)를 *"전체 조합 완전 동일성"* 으로 읽고 그 출력을 제출했는데, (b)를 필드별 비교로 고치면 **병합·GO 완료된 태스크에 증거 재제출 요구가 새로 생긴다.** `docs/DefinitionOfDone.md`가 완료를 *"AC-xxx are met"* 으로 정의하므로 문면이 바뀌면 완료의 근거 문서가 바뀐다. 이 저장소의 선례도 전부 신설 쪽이다(AC-074가 AC-064~067 위에 얹힘, AC-078이 AC-045·AC-060을 안 고치고 신설). 문면 변경은 사실 정정이라도 사용자 확정 사항이다(PRD v1.7 OQ-44 원문).

**How to apply:** reviewer·QA가 *"문면 위반은 아닌데 사용자 체감과 다르다"* 를 잔여 위험으로 넘겨올 때 적용. 태스크 행 안에 **선택지 3개 표**(제자리 수정 / 신설 / 문면 무변경+게이트 견고성)를 쓰고 각 행에 **소급 영향을 ①실질·②증거로 나눠** 적는다. **번호는 예약하지 않는다**([[ac-number-reservation]]) — *"확정 시점의 다음 미사용 번호(오늘 현재 AC-0xx는 참고값)"*. 그리고 **문면 판정을 태스크의 착수 게이트로 만들지 않는다** — 어느 결론이든 완료 증거는 같게 써 두면 사용자 확정을 기다리지 않고 구현이 굴러간다.
