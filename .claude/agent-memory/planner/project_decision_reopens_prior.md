**새 User 결정을 반영하기 전에, 그 결정 대상이 예전 OQ Decision란·architect 기각표에 이미 있는지 grep한다.** 2026-10-18 T191(PRD v1.24)에서 두 건이 걸렸다: ① D2 *"대면 편취"* = OQ-39(2026-07-25 *"E4 미채택"*)와 같은 대상 ② D3 *"다른 목소리로 재연결"* = `docs/Architecture.md` §22.2 B가 기각한 소켓 재연결(문맥 소실 · 미마스킹 전사 업로드).

**Why:** 전달문은 설계 초안 §4 표만 보고 만들어져 옛 결정을 언급하지 않았다. 그대로 적으면 옛 결정이 조용히 뒤집히고, 옛 기각 근거(안전 논거)가 새 구현에서 빠진다.

**⚠️ 반대 방향도 났다(2026-10-19, 내 실수):** AC-096 (b)를 설계 §2.1 표에서 옮기며 중급 *"D1·D2·D5(현행)"* 를 강제값으로 적었는데, 그 값은 2026-07-26 User가 *"강제하지 않는다"* 로 확정한 것이었다(`docs/Architecture.md:2069` · DECISIONS #44). 구현(S5)이 테스트 상수 예외로 드러냈다. ⇒ **설계 표를 수용 기준으로 옮길 때 칸마다 "(현행)" 표기 · 기존 확정 grep을 먼저 한다.** 이런 경우 User 재질문 없이 planner가 AC를 확정에 맞춘다(판정표 X-1~X-4 — PRD AC-096 갱신 고지 1).

**How to apply:** 결정 대상이 이름으로 같고 새 결정이 명시적이면 [[conflicting-user-decisions]]의 OQ 등재가 아니라 **재개**로 처리한다(옛 OQ Decision란에 시점 부착 · 재개 조건 충족 여부 대조 · *"User가 옛 결정을 염두에 뒀는지 기록 없음 — 확인 권고(비차단)"*). 옛 기각 근거는 새 AC의 조건으로 옮겨 *"architect가 다시 판정 · 해소 못하면 구현하지 않고 User에게 되돌린다"* 로 묶는다. 번호 범위가 지정돼 PRD OQ를 못 만들면 각 AC에 *"미결 + 확정 전 기본값(현행)"* 을 적고 태스크 행 F항에 모은다.
