**문서(주로 `docs/Tasks.md`·`docs/PRD.md`)의 수치를 고칠 때는 히트마다 "현재형 기준선"인지 "과거 기록"인지 먼저 판정한다.**

- **현재형 기준선 = 고친다.** *"앞으로 이 값을 기준으로 측정하라"* 는 뜻으로 미착수 태스크에 제시된 값(섹션 서두 기준값, `todo` 행의 "완료 판정 필수 증거 — before/after 기준 N").
- **과거 기록 = 보존한다.** *"그 시점에 이랬다"* 는 값(완료 행이 자기 수행 시점으로 적은 before/after, 병합 이력 서술, 특정 커밋 SHA가 붙은 실측).

**Why:** 이 저장소는 **과거 기록을 소급 재작성하지 않는 관례**가 있다(선례: MVP #28 "13종", OQ-40 Decision란 원문, T86 행의 `functions 427`을 T92 병합 후에도 보존). 동시에 미착수 태스크가 낡은 기준선을 들고 있으면 구현자가 틀린 before/after를 산출해 게이트 근거가 오염된다(T101 계열 사고).

**How to apply:**
1. 정정 전 **문제 수치와 새 수치를 모두 전수 grep**하고(`-o`로 히트 개수까지) 히트 전건을 표로 판정한다 — **부분 정정이 이 저장소의 반복 실패 양식**이다(한 세션에 5번: T92 행 4종↔6종 · 갭 번호 G38~G37 · T98 행 수치 · PRD AC-076 · PRD v1.7 변경 요약. 매번 한 자리만 고치고 같은 사실을 적은 다른 자리를 놓쳤다).
2. **다른 섹션이 그 값을 상호참조하는 문장**("위 섹션의 427은 병합 이전 값이며 건드리지 않았다")도 히트다 — 정정하면 그 서술이 거짓이 되므로 함께 갱신한다.
3. **오탐 확인**: 같은 숫자가 줄 번호·시각·다른 지표로 쓰인 자리가 있는지 본다. 오탐 정정은 새 오류다.
4. 고친 자리에 **정정 이력 한 줄**(원래 값 · 정정 근거 · 측정 커밋 SHA)을 남기고, **손대지 않기로 한 자리는 "미정정 1건"으로 명시**해 다음 패스가 놓치지 않게 한다.
5. **다른 에이전트가 점유 중인 행은 고치지 않고 보고만 한다** — [[planner-edit-only-handoff]] 참조.

테스트 수 측정은 항상 **`functions/lib` 삭제 후**여야 한다(T101). 관련: [[planner-ac-verifiability]]
