**한 결정은 넓게(*"수신화면에는 훈련용 표시 미진행"*), 다른 결정은 좁게(OQ-51 *"에스컬레이션 벨 프리롤 현행 유지"*) 같은 화면을 가리키면, "나중 것이 이긴다"·"구체적인 것이 이긴다" 어느 쪽으로도 planner가 정하지 않는다.** 판정표(N-1~N-4)를 먼저 고정해 ① 다툼 없는 범위(통화 진입 ①③)는 반영 ② 겹치는 범위(에스컬레이션 벨)는 User OQ로 올리고 **확정 전 기본값 = 먼저 확정돼 구현된 쪽(현행)** 으로 둔다. 이렇게 하면 구현 보류를 통째로 걸지 않고 **분기 1개만** 남는다(PRD v1.20 OQ-52 · T190 E).

**Why:** 2026-10-18 실폰형 재설계(PRD v1.20). 오케스트레이터는 *"정한다"* 를 요구했지만, User가 결정 7을 낼 때 에스컬레이션을 염두에 뒀는지 기록이 없다. 넓은 결정을 그대로 적용하면 직전에 같은 User가 명시적으로 고른 안을 조용히 뒤집는다. 기본값을 "현행"으로 두면 고지가 더 많은 쪽(안전 쪽)이기도 하다.

**결과(같은 날):** User는 OQ-52에서 planner 권고 (ㄴ)을 골라 OQ-51 ①을 스스로 뒤집었다. 그러니 OQ로 올린 것이 맞았다. 기본값을 미리 구현 가능하게 적어 둔 덕에 반영은 문면 몇 곳 정리로 끝났다(같은 버전 안에서 신설한 AC는 제출 증거가 0이라 제자리 정리).

**같은 패스의 부수 교훈:** 지시문이 *"AC-032(실존 브랜드·기관명 금지)"* 라고 인용했지만 AC-032는 링크 무해화 조항이고 브랜드 조항은 AC-033·045·072·M-8이었다 — AC 번호 인용은 행을 열어 문면 대조 후 쓴다([[premise-falsification]] 3차 사례와 같은 양식).

**How to apply:** User 결정 반영 지시를 받으면 결정마다 "대상 화면/경로" 열을 만든 대조표로 기존 User 결정(OQ Decision란 · 보충 행)과 겹침을 먼저 grep한다. 겹치면 OQ 선택지에 (ㄱ) 현행=기본값 (ㄴ)(ㄷ) 대안 + planner 권고를 적고, 구현 행(Tasks)의 "완료 판정 제외 범위"에 그 분기만 뺀다. 관련: [[user-scope-narrowing]], [[rule-table-extension]]
