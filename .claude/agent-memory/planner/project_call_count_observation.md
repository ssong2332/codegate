**"X가 N회 호출됐다(예상 M회)" 관찰을 받으면 판정·등재 전에 `src/` 에서 그 콜러블의 호출 지점을 전수 grep해 지도를 그린다** — 지점마다 (a) 마운트·효과에서 자동 1회인지 (b) 사용자 조작마다인지 (c) 프리페치·재시도·폴백 경로인지.

**Why:** 2026-10-02 `updateMessengerSkin` 5회(오케스트레이터 예상 "자동 1 + 수동 1")는 지도를 그려 보니 *마운트 자동 감지 1회(저장된 스킨이 없을 때만) + 수동 전환 **클릭마다** 1회(3종 순환)* 였다 — 클릭 4회면 설계대로다. 클릭 수가 보고에 없어 결함인지 판정할 수 없었다. 반대로 `createRealtimeCall` 같은 초 2회는 지도에서 **중복 가능 경로 2개**가 나왔다: 프리페치 중복 방지 가드가 ref를 **응답 도착 뒤**에야 채워 응답 대기 중 재호출을 못 막는다 + 프리페치 응답 전에 "받기"를 누르면 새로 발급한다. 둘 다 판독이지 실측이 아니라 원인은 미확정으로 남겼다(Tasks.md 섹션 서두 R3 기록).

**How to apply:**
1. 지도의 각 지점을 `파일:줄`로 적고 **"판독(실측 아님)"** 을 붙인다.
2. 사용자 조작에 비례하는 호출이면 **재등재 조건에 그 조작 수 기록**을 넣는다(예: *"(호출 수 − 클릭 수) ≥ 2이면 행으로"*).
3. in-flight 중복 방지 가드는 **ref를 await 앞에서 세우는지 뒤에서 세우는지**를 본다 — 뒤면 대기 중 재호출 경로가 열려 있다.
4. 관찰이 관련 OQ(예: 발급 횟수 상한 OQ-A85)의 **정상 흐름 쪽 데이터**인지 **남용 쪽**인지 구분해 적는다.
5. 판정표가 있으면 "관측 건수 · 기준선 비교 수단 · 사용자 표면 오동작" 세 조건을 각각 대조해 보이고, 표에 없는 케이스면 임의 판정하지 않는다.
