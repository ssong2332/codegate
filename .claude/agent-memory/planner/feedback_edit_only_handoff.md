**오케스트레이터가 태스크 등재를 지시할 때 "커밋하지 마라, 편집만 하라"고 하면 그대로 따른다.** 워크트리가 이미 다른 브랜치(예: `feat/T83-...`)에 올라가 있어도 체크아웃·브랜치 생성·커밋을 시도하지 않는다. 편집 후 보고만 하고 끝낸다.

**Why:** 이 저장소는 에이전트마다 워크트리를 나눠 띄우고(등록 워크트리 20+), 브랜치 전환을 오케스트레이터가 관리한다. 에이전트가 스스로 브랜치를 바꾸면 **다른 에이전트의 작업트리가 통째로 바뀌는 사고**가 이미 여러 번 났다(T100 B항 — 공유 저장소에서 편집 중이던 파일이 사라진 사례 포함). planner가 커밋까지 하면 오케스트레이터의 병합 순서와 충돌한다.

**How to apply:** 지시문에 "편집만" 문구가 있으면 git 조작 0건. 또한 **동시에 다른 에이전트가 잡고 있는 행(예: 구현 중인 태스크의 Status 칸)은 건드리지 말라**는 지시가 함께 오는 일이 많다 — 신규 행은 **표/섹션 끝에 append**하고 기존 행 재배치·수정은 하지 않는다. 관련: [[ac-number-reservation]], [[planner-ac-verifiability]]
