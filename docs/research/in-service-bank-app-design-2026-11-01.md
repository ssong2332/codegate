# 서비스 안 "내 은행 앱" 통일 설계 (2026-11-01)

## 금지 · 범위 (최상단)
- **설계 문서만.** 제품 코드 · 테스트 · 프롬프트 변경 0, 실 키 호출 0, 운영 Firestore 읽기 · 쓰기 0, `.env` · `.secret.local` 열람 0. 실 키 세션 수는 **제안**이며 단계마다 사용자 승인이 필요하다.
- 이 문서는 기획안 `in-service-experience-plan-2026-10-31.md` D1의 **(b) "훈련용 휴대폰 홈 + 가상 은행 앱"**을 구체화한다. D1은 "(a)로 시작, (b)는 P6 뒤 재검토"로 확정돼 있다. 이 설계로 (b)를 앞당길지 여부도 사용자 결정이다(§6 BA0).
- 실존 은행 · 기관 이름 0. 가상 은행명은 `FICTIONAL_BANK_NAMES`(가온은행 · 미르은행 등 8개, `functions/src/shared/fictionalBank.ts:20`) 그대로 쓰고, 1회 한도 1,000만 원(P2-d `transferLimitError`)도 그대로 둔다.
- **겹치지 않는 범위**: 같은 시기 P2 세션이 예금주 이름 · 메신저 송금 카드 미리보기 · 문자방 제목을 손보고 있다. 이 문서는 그 결과를 **전제로만** 쓰고, 그 부분의 수정안은 내지 않는다.
- 표기: **확인** = 파일:줄 또는 원문 출처가 있음, **추정** = 추론(확인 방법 병기), **미확인** = 출처를 찾지 못함. 웹 출처는 모두 **검색 결과 요약 기준**이다. 원문 페이지는 열지 않았다.

## 0. 판정표 (이 표대로만 분류한다)
### 0.1 은행 앱 진입 방식 판정표 (§1 "진입" 열)
| # | If (지금 그 루트에서 계좌가 참가자에게 오는 방식) | Then (은행 앱 진입) |
|---|---|---|
| E1 | 통화 중 문자에 계좌가 적혀 온다 | **문자 계좌 길게 눌러 복사 → 통화 화면 "홈" → 은행 앱 → 받는 계좌에 붙여넣기** |
| E2 | 메신저 대화에 계좌가 온다 | **말풍선 길게 눌러 복사 → 대화방 밖 홈 → 은행 앱 → 붙여넣기** |
| E3 | 사기범이 계좌를 말로 부른다 (문자 · 메시지 없음) | **통화 화면 "홈" → 은행 앱 → 받는 계좌를 직접 입력**(받아 적은 값). 서버는 그 값을 받지 않는다 |
| E4 | 원격제어(보안 점검) 앱 설치에 응낙한 뒤 이체 단계가 온다 | **E1 진입 + "원격 지원 연결됨" 띠.** 화면이 저절로 움직여 인증 직전까지 간다(사기범 조작 표현). **인증 버튼만 참가자가 누른다** |
| E5 | 이체가 아니라 현금 · 금 · 상품권 · 대출 실행이 결말이다 | 이번 범위 밖. P4 · P5에서 같은 은행 앱 안 메뉴(대출 · 해지 · 출금 예약)로 붙일 **자리만** 둔다(§2.4) |
| E6 | 코인 거래소 경유(검찰 `asset-check-site` · `asset-check-wallet`) | 이번 범위 밖. 현행 사이트를 유지한다(§6 BA9) |
표에 없는 경우가 나오면 임의로 판단하지 않고 행을 추가할지 메인에 묻는다.
