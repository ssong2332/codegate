# 통화 사기범 음성 혼합안 — Live 출력 자막 → 문장 단위 Chirp 3 HD 설계 (2026-11-23)

## 금지 · 범위 (이 문서 전체에 먼저 적용)
- ⛔ **설계 문서다.** 코드 변경 0 · 실 키 호출 0 · 배포 0. 아래 실측 계획(§9)은 **계획만** — 실행은 매번 사용자 승인.
- ⛔ 수치 표기 규칙: **실측** = 2026-10-20 프로토타입(메인 체크아웃 `prototypes/voice-cascade/`, 미커밋 · 읽기만) 결과 파일에 있는 값. **출처** = 공식 가격 페이지. 그 밖은 전부 **추정**이며 확인 방법을 붙였다.
- ⛔ 사기범 음성에 실존 기관 · 회사명이 나가면 안 된다 — 혼합안은 이를 **합성 전에** 막을 수 있다(§6.3). 프로토타입 지시문에 실존 기관명이 있었으나 그것은 측정용이며 운영에 옮기지 않는다.
- ⛔ ElevenLabs는 실서비스 제외(사용자 결정 2026-10-20). 이 문서의 비교 대상이 아니다.
- ⛔ 비밀값(`.env` · `.secret.local`)은 열지 않았다. 프로토타입 키 이름만 스크립트 소스에서 확인했다.
- ⚠️ 사용자 결정 2026-11-19 *"내가 지출해야 하는 금액은 0원"*(PR #589 복제 설계)이 이 기능에도 걸리는지는 **결정 항목 D1**이다. 이 문서는 "걸린다"고 보고 0원 안에서 성립하는 형태를 기본안으로 잡았다.

## 4. 서버 중계 방식
전제: Chirp 스트리밍 합성(`StreamingSynthesize`)은 **gRPC 양방향 스트림**이라 브라우저에서 직접 못 부른다. 키를 브라우저에 둘 수도 없다.

| # | 방식 | 첫소리 영향 | 0원 | 판정 |
|---|---|---|---|---|
| R1 ⭐ | **Functions 2세대 HTTP(`onRequest`) — 문장 1개 = POST 1개.** 함수가 gRPC 스트림을 열어 문장을 넣고, 오는 PCM 청크를 HTTP 응답으로 바로 흘려 보낸다(chunked). 클라는 `fetch` + `ReadableStream`으로 받아 재생 큐에 넣는다 | 클라 ↔ 함수 왕복 + 함수 ↔ TTS. 서울 리전이면 +50~150ms, `us-central1`이면 +200~350ms(추정 · 확인 = M2) | Functions 무료 구간 안(추정 · 확인 = 결제 보고서) | **권장.** WebSocket 불필요 — 문장마다 스트림을 새로 여는 방식(§2 실측)과 요청 단위가 맞는다 |
| R2 | Cloud Run WebSocket 서비스 — 통화 1개 = 소켓 1개, 서버가 Chirp 연결을 유지 | 요청마다 연결 비용 없음(−수십 ms 추정) | Cloud Run 무료 구간 · 이미지 저장(#589 Z3 · Z4)과 같은 조건부 | 보류 — 새 배포 단위 · 60분 요청 상한 · 인증을 직접 만들어야 한다 |
| R3 | Functions가 짧은 OAuth 토큰 발급 → 브라우저가 REST `text:synthesize` 직접 호출 | 비스트리밍이라 문장 전체가 끝나야 재생(+0.5~1초 추정) | 토큰이 유효한 동안 남용 가능 → 0원 깨질 위험 | ⛔ 기각 |
| R4 | Callable 함수 스트리밍(`sendChunk`) | R1과 같음 | 같음 | 대안. firebase-functions 7.x의 스트리밍 callable이 바이너리 청크를 다루는 방식은 미확인 — 확인 후 R1과 택1 |

**R1 함수가 지킬 것(신뢰 경계):**
| # | 검사 | 실패 시 |
|---|---|---|
| T1 | Firebase ID 토큰 검증(익명 포함) · 세션 소유자 · 세션 `active` | 401/403 → 클라는 그 턴 Live 폴백 |
| T2 | 목소리는 **서버가 세션 · 레그에서 정한다**(요청에 목소리 이름을 받지 않는다) | — |
| T3 | 요청당 글자 상한(예: 200자) · 세션당 글자 상한(예: 6,000자 — 20분 상한 통화 추정치 4,100자의 1.5배) | 413/429 → Live 폴백 |
| T4 | 서버 쪽 실존 기관명 가드(`functions/src/realtime/liveTranscriptGuard.ts`) 재적용 — 클라가 조작돼도 소리에 실존 이름이 안 나간다 | 걸린 부분 치환 후 합성 |
| T5 | 월 글자 카운터(Firestore `FieldValue.increment` · 합성 뒤 비동기 가산) — 상한(D2) 넘으면 거절 | 429 → 통화 전체 Live 폴백 |
| T6 | 응답에 텍스트 · 키 · 목소리 이름을 싣지 않는다(PCM만) | — |

| H1 | 사기범 말하는 중 판정 | `agentSpeaking`의 원천을 **Chirp 재생 큐**(예약된 소스 + 아직 안 온 문장)로 바꾼다. Live `turnComplete`는 Chirp보다 0.3~0.6초 먼저 온다(추정 — §2 첫 자막과 첫소리 차이) — 그때 마이크를 열면 자기 소리가 마이크로 들어간다 |
| H2 | 마이크 다시 열기 | Live `turnComplete` 수신 **그리고** Chirp 큐가 빔 + `TAIL_GRACE_MS` — 기존 `agentSpeechGate` 규칙에 "아직 올 문장 있음"을 진행 중 턴으로 넣는다. 정지 상한(`stallGraceMs` 4초)은 유지 |
| H3 | 서버 `interrupted` | `stopAllPlayback` + **진행 중 R1 요청 전부 `AbortController.abort()` · 남은 문장 폐기 · Live 버퍼 폐기** |
| H4 | 사고 문장 게이트 발동 · 통화 종료 · 참가자 끊기 · 레그 넘김 · 재연결 | H3과 같은 정리 함수 1곳 |
| H5 | 사기범 `end_call`(끊기 R5 배수) | "잔여 재생"에 Chirp 큐를 포함 — 마지막 문장이 다 나간 뒤 끊는다 |
| H6 | 참가자 음성 끼어들기 | **지금처럼 막혀 있다**(반이중 — 바꾸지 않는다). Live 턴이 끝났는데 Chirp가 아직 말하는 구간(H1)에도 막는다. 진짜 끼어들기는 에코 제거 과제라 별도 |
| H7 | 타이핑 턴(`sendClientTurn`) | 지금 보류 큐 규칙 그대로. "턴 끝"을 Chirp 재생 끝으로 본다(H2와 같은 신호) |

### 6.3 자막 · 저장 전사 정합
| # | 항목 | 규칙 | 이유 |
