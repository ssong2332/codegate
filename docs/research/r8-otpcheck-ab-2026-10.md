## 6. 한계
1. 텍스트 폴백만 재현했다. PII 마스킹·`limitReplySentences`·`finalizeScammerReplyText`·과부하 대체 모델·Groq·Mock 강등은 생략(S1 §5와 같음).
2. 표본: 커밋당 7세션(대본 2종), 시나리오 1종, 난이도 고급만. 모델 출력은 확률적이다.
3. 요구 범주는 키워드+수동 판정이다. 판정자 1명(이 에이전트).
4. 프롬프트는 각 커밋의 **빌드 산출물**로 조립했고, 앱의 Firestore 도착 판정은 메모리 집합(`fbDelivered`)으로 대체했다(도착 턴 이후 항상 도착으로 판정 — 앱의 정상 경로와 같음).
5. pre·post를 번갈아 돌렸지만 같은 시간대 15분 안이라 API 쪽 상태 변화의 영향은 배제하지 못한다(429 0건).
