# ADR-0015: 실시간 통화의 사건 발동 시점을 모델에게 넘긴다 — Gemini Live function calling + 턴 게이트 하한 + 카운터 백스톱

- Status: accepted
- Date: 2026-09-06
- Owner: architect
- DECISIONS.md entry: #96 (User 확정 — **OQ-A66 resolved**)
- 관련: Architecture.md **§59**(구현 스펙 정본) · §57.8 (라) · §57.9 · §57.10 ③ · UX-027/UF-008 · UX-031/UF-011 · AC-059/AC-060/AC-061 · AC-071
- 관계: **ADR-0007을 뒤집지 않는다.** ADR-0007의 앱 오케스트레이션 모델은 **백스톱 경로로 그대로 남아** 결정론적 도착을 계속 보장한다. 본 ADR이 바꾸는 것은 **그 경로가 유일한 경로였다는 것** 하나다. ADR-0007이 후보표에서 function calling을 기각한 4사유는 §59.2·아래 Context에서 **행 단위로 재판정**했다.

## Context

**신고와 요구.** 사용자가 라이브 관측 뒤 *"시나리오는 단순히 흐름이어야 하고, 가해자가 대화의 흐름을 이끌어가야 한다"* 고 요구했다. §57이 그 요구를 코드로 번역한 결과, 오늘 실시간 통화에서 **사건(문자 도착·확인창구 오퍼)의 시점을 정하는 것은 전부 정수 카운터**임이 확인됐다(`inCallSms.ts` `afterScammerTurns` · `verifyIntercept.ts` `availableAfterScammerTurns`).

**그 구조가 만든 두 결함.**
- **T-2** — 문자는 Firestore write 즉시 도착하는데 예고 대사는 콜러블 왕복 → 큐 → `sendClientContent(turnComplete:true)` 를 거쳐 **별도 턴**으로 들어간다 ⇒ 도착과 예고 사이에 상한 없는 간격이 생긴다.
- **T-4** — 그 주입이 `turnComplete:true` 라 **모델이 즉시 새 턴을 발화**하고, 참가자에게 열리는 창이 사라진다(§52.7).

**⭐ 두 결함은 같은 값 위에서 반대 방향이다**(§57.6): T-2는 드레인을 *더 빨리*, T-4는 *더 늦게* 요구한다. 3열 표(제약 → 실제 요구 → 그것을 아는 층)로 층을 가르면 **값으로 표현 불가한 행이 둘이고 둘 다 "모델만 아는 것"**(자기 턴의 시작·끝)이다 ⇒ **모델에게 시점을 넘기는 것은 취향이 아니라 이 문제의 해다.**

**ADR-0007이 function calling을 기각한 4사유 — 2026-09-06 재판정.**

| ADR-0007의 사유 | 오늘 판정 | 근거 |
|---|---|---|
| ① *"의도적으로 잠근 `tools: []` 보안 설계를 건드림"* | ⚠️ **약화** | 잠금의 취지는 주석이 스스로 적는다 — *"이걸 잠그지 않으면 **클라가 임의 도구를 주입**할 수 있다"*(`geminiProvider.ts:187`). **서버가 목록을 선언하는 것은 그 취지를 어기지 않는다**(도구는 토큰에 서버 고정, 클라 주입 경로는 그대로 닫힌다) |
| ② 배선 복잡도 · **프로바이더별 규약 차이**(ElevenLabs client tools) | ⭕ **유효하나 미발동** | 범위를 **Gemini 실시간 1경로**로 좁힌다. ElevenLabs 경로는 `firstMessage`/에이전트 프롬프트 계열이고 §21이 소유한다 — 이 ADR은 그쪽에 **0줄** |
| ③ `toolResponse` 왕복을 오디오 루프에 넣어야 한다 | ⭕⭕ **해소** | **P-A 프로브 판정 A(완전 지원)** — 오디오 모달리티에서 `toolCall` 수신 → `sendToolResponse` → `outputTranscription`/`turnComplete` 정상 진행이 라이브 1호출로 실측됐다. SDK 타입도 정합(`genai.d.ts:9262`·`:9322-9325`·`:12177`·`:9201-9204`, `responseModalities`와 `tools`가 같은 `LiveConnectConfig`에 공존) |
| ④ ***"그러고도 도착을 보장 못 한다"*** | ⭕⭕ **여전히 유효 — 그러나 백스톱이 그것을 없앤다** | AC-059/060/061은 결정론적 도착을 요구한다. **하한+N 경계까지 모델이 부르지 않으면 앱이 오늘 경로로 발동시킨다** ⇒ 보장이 복원된다. ⭐ 메모리 `feedback_rejected_candidate_revives_with_backstop`의 정면 사례 — *"보장 못 한다"* 만 남았을 때 **기존 경로를 천장으로 남겨 사면 산다** |

**⭐ 착수 전에 발견한 것(이 ADR이 없으면 반드시 밟는 지뢰).** 시스템 프롬프트가 **도구 호출을 명문으로 금지하고 있다** — *"문자가 실제로 도착한 순간에는 그 사실을 알리라는 **별도 지시가 이 프롬프트에 함께 들어온다** — 그 지시가 없을 때 문자를 보냈다고 말하지 않는다"*(`promptAssembly.ts:74`), *"**앱의 안내 지시가 오기 전에는 확인 창구 이름을 먼저 꺼내지 않는다**"*(`:227`), *"지시가 이 프롬프트에 함께 들어온 턴에만 창구 이름을 말한다"*(`:228`). **도구만 선언하면 모델은 부르지 않는다.**

## Decision

**실시간(Gemini Live) 경로에서 문자 도착과 확인창구 오퍼의 *발동 시점*을 모델의 function call로 넘긴다. 단 (1) 하한은 기존 턴 게이트가 그대로 지고 서버가 재검증하며, (2) 하한 이후 N 경계 안에 모델이 부르지 않으면 앱이 오늘 경로로 발동시킨다(천장). 이름: "턴 게이트는 바닥, 모델이 시점, 카운터가 천장".**

| Option | Pros | Cons |
|---|---|---|
| **(라) 하이브리드(채택) ✅** — 하한(턴 게이트) + 모델 시점(도구) + 천장(백스톱) | **T-2 간격 0**(도착과 예고가 같은 모델 턴 안) · **T-4 주입 0건**(도구 응답은 턴 슬롯을 0개 쓴다) · **도착 보장 유지**(백스톱) · 자유텍스트 분류 **0건** · **AC-060 원문의 *"사기범 턴에 실린 구조화 신호"* 에 오늘 구현보다 더 가깝다** | 클라에 `toolCall`/`sendToolResponse` **신규 배선** · 콜러블 계약 **증분 3건** · 프롬프트 **조건부 치환 3줄** · 백스톱 상수 **2개가 판단값**(라이브 미검증) · 모델이 *"적절한 때"* 를 고를지는 **P-E 전까지 미검증** |
| (나') function calling **단독**(백스톱 없음) | 배선이 더 단순 | ⛔ **기각 — ADR-0007 사유 ④가 그대로 살아난다.** 모델이 안 부르면 문자가 영영 안 오고 **AC-059/060/061이 무너진다** |
| (가) 대화 상태(자유발화 분류) 트리거 | 대사와 완벽 동기 | ⛔ **기각 유지** — `PRD.md:199` OQ-16 확정(*"LLM 자유 감지 MVP 제외"*)에 정면 위배. 그보다 **구조적으로 불가능**하다: 실시간에서 서버는 통화 중 참가자 발화를 볼 수 없고(전사는 종료 직전 1회), 클라가 판정하면 **안전 판정을 클라가 쥔다**(§16.1.3/G84) |
| (나) sentinel 토큰 `[[SMS:id]]` | ADR-0007 후보표 그대로 | ⛔ **기각 유지 · 논거 무변경** — 응답 모달리티가 오디오 고정이라 서버가 텍스트를 쥐는 지점이 없고 **모델이 마커를 낭독한다** |
| (다) 순서 보장만(발화 먼저·도착 나중) | T-3·T-4를 닫는다(이미 `fd6e325`로 병합됨) | ⚠️ **부분 채택이되 이 ADR의 대안은 아니다** — **T-2 간격을 0으로 만들지 못하고**, *"흐름을 이끈다"* 는 요구를 **하나도** 충족하지 않는다 |
| 무조치 | 비용 0 | ⛔ T-2가 남고 사용자 요구가 미해소 |

**부수 결정(같은 맥락이라 함께 못박는다 — 상세는 Architecture.md §59).**

1. **도구는 인자를 갖지 않는다**(`send_prepared_sms` · `offer_verification_desk` 둘 다). `smsId`·`offerId`를 인자로 주면 **카탈로그 선택권이 모델로 넘어가** `findInCallSmsItem`/`findVerifyInterceptItem`의 G12/G24 재검증이 형해화된다. 회귀 게이트가 `parameters.properties` 빈 객체를 기계로 단언한다.
2. **`announceInstruction`은 별도 텍스트 턴이 아니라 *도구 응답 페이로드*로 간다.** 이것이 T-2·T-4를 동시에 닫는 유일한 기전이다 — 도구 응답은 모델이 진행 중인 자기 턴 안에서 소비되므로 **턴 슬롯을 0개 쓴다**.
3. **모델에게 돌아가는 한국어 문자열은 전부 서버가 소유한다**(성공 `announceInstruction` · 거절 `declineInstruction` · 실패 `failureInstruction`). 실패 문자열은 `createRealtimeCall` 자격증명으로 내려보낸다 — 클라가 저작하면 G86-a/b/c·G101이 카탈로그 필드로 묶어 둔 것이 풀린다.
4. **도구 이름을 클라에 하드코딩하지 않는다.** `createRealtimeCall` 응답 `liveTools`로 내려받아 비교한다 — 드리프트 게이트를 만드는 대신 **드리프트가 성립할 자리를 없앤다**.
5. **`deliverVerifyReconnect`(호 전환 실행)는 도구로 노출하지 않는다.** 그 인과의 주체는 **참가자의 탭**이다(§22/ADR-0013). 모델이 부르면 참가자가 누르지 않은 전환이 일어난다. `endSession`·`recordInCallSmsEvent`도 같은 이유로 기각.
6. **프롬프트 3줄은 삭제가 아니라 조건부 치환**한다(신규 옵션 `toolDrivenTiming` 1개, `geminiProvider.ts` 호출부에서만 `true`). 부재·`false`면 조립 문자열이 **바이트 단위로 오늘과 동일**하다. **폴백(텍스트) 경로에는 넘기지 않는다** — 그쪽엔 Live 세션이 없어 도구가 존재하지 않는다.
7. **verify 2단계(announce → commit)는 도구 경로에서도 유지한다**(§38.4 E). 컨트롤은 여전히 예고 턴이 끝난 뒤에만 뜬다.
8. **`offer_verification_desk`는 오늘 계열 A(`bank-security-verify-scam` 1종)에만 선언한다.** 계열 B 5종 확장은 **OQ-A73**(User) — 사용자가 **두 번** 축소를 요구한 컨트롤이라(§47 신고 ③-b · §49 신고 7) architect가 단독 확정하지 않는다. `verifyIntentExpressed`는 **되살리지 않는다**.
9. **Firestore 스키마 0건 증가.** 어느 경로로 도착했는지는 **서버 로그**로만 관측한다.

## Consequences

- **Positive**
  - **T-2가 구조적으로 사라진다** — 도착과 예고가 같은 모델 턴 안에 있다.
  - **T-4 주입이 0건이 된다**(도구 경로) — 참가자의 차례를 뺏지 않는다. 백스톱 경로에서만 오늘의 주입이 남고, 그때는 §52.7 처방(`fd6e325`)이 이미 덮는다.
  - **AC-060 원문에 더 가까워진다** — 그 조항이 요구한 것은 *"사기범 턴에 실린 **구조화 신호**"* 이고, function call이 정확히 그것이다. **자유텍스트 분류는 0건 도입한다.**
  - **하한이 클라 단독 → 서버 재검증으로 한 칸 강화된다**(오늘 `deliverInCallSms`에는 턴 인자가 아예 없다).
  - 도구가 없는 세션(카탈로그 없음 · Mock/폴백 강등 · ElevenLabs · 계열 B verify)은 **오늘 경로와 바이트 단위로 같다**.
- **Negative / accepted trade-offs**
  - **백스톱 상수 2개(`TOOL_WINDOW_MAX_BOUNDARIES=2` · `TOOL_WINDOW_STALL_SEC=90`)는 판단값이며 라이브로 검증되지 않았다**(`STALL_GRACE_MS`·`prefixPaddingMs`와 같은 형식). 틀리면 P-E가 `backstop` 100%로 드러낸다.
  - **모델이 "적절한 때"에 부를지는 미검증이다.** P-A가 보인 것은 *"부를 수 있다"* 뿐이다 — 이 ADR의 핵심 가치(흐름 주도)는 P-E 전까지 가설이다.
  - **거절(`too_early`)을 받은 모델이 그 지시를 지킬지 검증하지 못했다.** 지키지 않으면 UF-008 Failure (a)("말은 했는데 문자가 안 옴")가 **간격 형태로** 재현될 수 있다. 완화 수단은 있으나(도구 실패·거절 뒤 백스톱 창 즉시 닫기) **간격 자체를 0으로 만들지는 못한다.**
  - 하한 재검증은 **클라가 신고한 턴 수**에 대한 것이라 위조 클라를 막지 못한다. 위조의 최대 효과는 오늘과 동일하게 *"자기 훈련용 모의 문자를 조금 일찍 보는 것"* 이다(`callTypes.ts:30-31`).
  - `toolCallCancellation` 처리 규약은 **실측하지 못했다**(정한 규약: 아직 콜러블을 부르지 않았으면 부르지 않고, 이미 불렀으면 되돌리지 않는다 — 문자는 이미 도착했다).
  - 클라 배선·콜러블 증분·프롬프트 치환·백스톱 4층이 **커밋 5개로 나뉜다**(§59.10). 순서를 어기면 **통화가 멈추거나**(도구 선언이 클라 배선보다 앞설 때) **모델이 없는 도구를 부르겠다고 말한다**(문면이 선언보다 앞설 때).
- **되돌리는 비용**
  - `geminiProvider.ts`의 `tools`를 `[]`로 되돌리고 `toolDrivenTiming`을 넘기지 않으면 **그 순간 오늘 동작**이다(클라 배선·콜러블 증분은 남아 있어도 발동하지 않는다). 백스톱 창은 `credentials.liveTools` 부재 ⇒ 즉시 발동으로 자동 복귀한다.
- **Follow-ups required**
  1. **P-D**(관측 세션이 Mock 강등이 아님을 서버 로그로 확인) → **P-E/P-F**(라이브 1통화 — 도구 호출 횟수·`status` 분포·도착 경로 비율·T-4 재현 0건).
  2. **OQ-A73 확정**(User) 후 계열 B 5종 확장 — 선언 조건 1줄 + 회귀 게이트 기대 집합 갱신(architect 후속 패스).
  3. planner: `docs/Tasks.md`에 커밋 A~E 담당 행 등재.
  4. `send_prepared_sms`가 여러 항목을 가진 시나리오에서 **어느 항목을 보낼지 서버가 고르게** 한다(§59.13 (6) — 클라가 고르면 `too_early`와 `none_pending`이 구분되지 않는다).
