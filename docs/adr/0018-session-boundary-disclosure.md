## Context

User가 *"세션 중 '모의' 표시를 어떻게 바꿀까요?"* 에 ***"전부 제거"*** 로 답했다(선택지 설명: *"카카오 면책까지 빼고 메신저에 시작 전 고지를 새로 둔다. AC-047 변경과 법무 확인이 필요하다."* · 원 요청 *"이건 처음에만 이야기 하고, 그 이후 테스트에서는 확인할 수 없도록"*). PRD v1.18이 판정표 P6-M(M-1~M-13)으로 정책을, UX v1.30이 화면 규칙(P-36)을 확정했다.

이 저장소의 기존 구조 결정 두 개가 이 정책과 정면으로 부딪친다:
1. **ADR-0014 (B)** — *"화면이 X를 했다고 말하면, 고지는 X를 하지 않았다고 말한다"*(세션 중 같은 화면에서). 구현은 공유 헤더 배너 · 제출/설치 직후 부정 고지 · 확인 전환 줄(G272)이고 `functions/src/scenarios/__tests__/mockScreens.test.ts`의 G-D가 그 상수를 지킨다.
2. **DECISIONS #7 / #19** — 화면 상시 라벨(`SyntheticLabel`) · 카카오 면책 *"영구 비활성화 불가·항상 노출"*.

동시에 고지는 사라지면 안 된다 — AC-087(모든 진입 경로 · 세션마다 · 우회 불가) · AC-089(모든 종료 경로)가 고지를 **세션 경계로 옮기라**고 요구한다. 그런데 **세션 전 문면과 세션 중 화면이 같은 파일에 공존한다**(`src/app/session/play/page.tsx`의 `PREROLL_NOTICE` · 메신저에 새로 들어올 시작 고지). 파일 단위 낱말 검사는 그 공존 때문에 오탐한다(UX P-36 (7) ②).

## Decision

**훈련이라는 사실은 세션 경계 두 곳에서만 말한다 — 시작 전(세션마다 · 탭 게이트) · 종료 후(모든 종료 경로의 공통 착지 UX-007). 세션 중 화면의 앱 고유 문면에는 표식을 두지 않고, 그 성질을 *구조*로 보장한다.**

**(1) 세션 경계 문면은 모듈로 분리한다** — 세션 전 문면은 `src/lib/sessionboundary/preSessionCopy.ts`, 세션 후 문면은 `src/lib/sessionboundary/postSessionCopy.ts`에만 리터럴로 존재한다. 세션 중 화면을 그리는 파일(통화·메신저 페이지, 오버레이 3종)은 그 값을 **식별자로만** 참조한다. ⇒ 세션 중 파일의 **리터럴 낱말 검사가 다시 파일 단위로 성립**하고, 식별자 쪽은 **AST 사용처 가드**(세션 전 상태 분기 안에서만 렌더)로 *상태*에 묶는다. 판정 단위는 파일이 아니라 상태이고, 이 분리가 그 판정을 기계로 가능하게 만든다.

**(2) 메신저 시작 고지는 세션 라우트 안의 첫 상태다**(UX D-78) — 확인 탭 전에는 대화 구독을 시작하지 않고(통화의 *"받기 전 구독 안 함"* 과 같은 규칙), 확인 기록은 통화 *"받기"* 기록과 **같은 범위**(탭 범위 `sessionStorage` · 값 = 세션 id · `clearPendingSession()`에서 삭제)에 **다른 키**로 둔다. ⛔ **같은 키를 재사용하지 않는다** — 재사용하면 메신저→통화 에스컬레이션 세션이 통화 화면에서 *"이미 받은 세션"* 으로 판정돼 벨 화면 프리롤을 건너뛴다(T30이 고친 회귀의 재발 · `docs/PRD.md` OQ-51 확정 전 현행 유지 위반).

**(3) ADR-0014 (B)의 규범은 폐기하지 않고 층을 옮긴다** — *"화면이 X를 주장하면 X를 부정한다"* 는 **세션 후 사실 공개 상수 1개**(UX D-82)가 진다. 세션 중 화면이 주장하는 행위 종류(정보 제출 · 이체 · 설치/권한 · 전화 연결)마다 그 상수가 부정해야 할 낱말을 **등록부로 대응**시키고, 새 주장 종류(새 `MockScreenKind` 등)가 등록 없이 생기면 게이트가 실패한다. 갈래 0(ADR-0014 (B)의 *"갈래를 늘리지 않는다"*)은 그대로 계승한다.

**(4) 프롬프트 문면은 두 층으로 가른다** — 모델이 **말하거나 수행할 대사·행동의 예시**(따옴표 안 대사 · 행동 예시 목록 · 행동을 지칭하는 섹션 제목)는 *대사 층*이라 표식 낱말 0, 모델에게 상황·제약을 알리는 문장(가드레일 · *"페이로드는 가상값만"* 류 무해화 지시)은 *메타 층*이라 **닫힌 허용목록** 안에서만 낱말을 허용한다(AC-005 · AC-024 불변).

| Option | Pros | Cons |
|---|---|---|
| **A. 경계 문면 모듈 분리 + AST 사용처 가드(채택)** | 세션 중 파일의 리터럴 검사가 단순 · 오탐 0 · 법무 결론으로 문면이 바뀌면 **두 모듈만** 고친다 | 모듈·게이트가 하나씩 는다 · 식별자 가드가 AST 구조(조건 `&&` · 조기 `return`)에 의존한다 |
| B. 파일 단위 낱말 검사 + 파일별 예외 문자열 목록 | 구현이 가장 짧다 | ⛔ 예외 문자열이 같은 파일의 **세션 중 분기**에 다시 써져도 통과한다 — 상태를 보지 못한다(UX P-36 (7) ② 그 자체) |
| C. 렌더 하네스로 상태별 정적 렌더 | 상태를 직접 본다 | ⛔ 페이지는 Firebase·라우터 훅이 있어 하네스(§32/§39 — 1개 컴포넌트 고정)로 렌더할 수 없다 · 하네스 범위 확대는 §39의 격리 결정을 다시 연다 |
| D. 확인 기록을 Firestore 세션 문서에 둔다 | 탭·기기 간 유지 | ⛔ 신규 필드 · 쓰기 경로 · rules · Functions 배포가 생긴다(API/DB 델타) · 클라 주장값이라 신뢰도 이득이 없다 · UX N-3(*"모르면 다시 띄운다"*)이 이미 안전 쪽을 정했다 |
| E. 확인 기록에 `session.answeredSessionId` 재사용 | 코드 0줄 | ⛔ 위 (2)의 T30 회귀 재발 |

## Consequences

- **Positive:**
  - 세션 중 화면 6종의 표식 0건을 **소스 게이트로** 판정할 수 있다(AC-086 (b)(c)(d)(g)) — 판정 대상 등록부가 `src/components/*.tsx` · `src/app/session/*/page.tsx` 디렉터리와 일치하지 않으면 실패한다.
  - 고지가 **세션마다·우회 불가**가 된다 — 메신저도 통화와 같은 *"라우트 안 첫 상태 + 탭 게이트"* 다(AC-087 (b) · AC-088 (b)).
  - **서버 계약 · 스키마 · 콜러블 · rules 변경 0** — 프롬프트 문면 2곳을 빼면 전부 Hosting 산출물이다.
- **Negative / accepted trade-offs(⛔ 숨기지 않는다):**
  - ⭐⭐ **카카오 상표 accepted risk(OQ-18)의 완화책이 시작 전 1줄로 줄었다**(OQ-24/AC-047 → UX D-80). 법적 충분성 **미확인**(OQ-49 (a)).
  - **인공지능기본법 투명성 의무**(공개 2차 자료상 사전 고지 + 결과물 표시 — 추정) 충족 여부 **미확인**(OQ-49 (b)). 세션 중 결과물 표시는 0이다.
  - **표식 없는 세션 화면 캡처**가 실제 사기 화면처럼 유포될 수 있다(OQ-49 (c)). 무해화(실 URL·실계좌·실 기관명·실존 앱명 0)는 그대로라 캡처가 *실행 가능한* 사기 정보를 담지는 않는다.
  - **확인 전환 화면에서 *"실제로 전화가 걸리지 않습니다"* 가 빠진다**(G272 반전) — 참가자가 실제 발신으로 오인할 여지가 세션 동안 열린다. 부정은 종료 후에야 온다. **오인 빈도 관측 0**.
  - 확인 기록이 탭 범위라 **다른 탭·기기에서 같은 세션을 열면 시작 고지가 한 번 더 뜬다**(UX N-3 — 안전 쪽 오차로 수용).
  - ADR-0014 (B)의 *"같은 화면 안의 즉시 부정"* 이 *"세션 후 1회 부정"* 으로 약해진다 — 규범은 남지만 **시점이 늦어진다.**
- **Follow-ups required:**
  - **User**: 이 설계 승인 · OQ-50(법무가 착수/배포 중 무엇을 막는가) · 가능하면 OQ-51(에스컬레이션 도중 프리롤).
  - **User → 법무**: OQ-49 (a)(b)(c). 결론이 *"세션 중 일부 표식 필요"* 면 이 ADR을 supersede하는 새 ADR + AC-086 (f) 닫힌 예외 행 추가(User 결정).
  - **implementer**: `docs/Architecture.md` §72.6 파일별 변경 · §72.7 게이트 G436~G450 · §72.8 깨지는 테스트 처리(⛔ 게이트 삭제로 통과 금지 · 재작성마다 역검증 1건).
  - **planner / User**: `docs/Architecture.md` §72.12 OQ-A92(한도 종료 뒤 셸에서 이탈 시 사실 공개 미도달 칸) · OQ-A93(저장소 밖 ElevenLabs 에이전트 프롬프트).
