# ADR-0017: Gemini Live 모델을 `gemini-3.8-live`로 바꾸되 2.5의 턴·도구 의미를 보존한다 — 도구 `BLOCKING` 명시 + 클라 턴 보류 큐

- Status: proposed (User 승인 대기 — Architecture.md §70)
- Date: 2026-10-17
- Owner: architect
- DECISIONS.md entry: #115
- 관련: Architecture.md **§70**(구현 스펙 정본) · §59 / ADR-0015(모델 주도 도구 시점) · §50.8(지연 판정 · P-0) · §25.3(A5-α `turnComplete:false`)
- 관계: **ADR-0015를 뒤집지 않는다.** 도구가 "결과를 받은 뒤 이어 말한다"는 ADR-0015의 전제를 3.8에서도 성립시키는 것이 이 ADR의 목적이다.

## Context

현행 실시간 통화 모델 `gemini-2.5-flash-native-audio-preview-12-2025`(`functions/src/realtime/geminiProvider.ts:26`)는 Google 폐기 페이지(2026-10-12 갱신)에 **종료일 2026-11-17**(가장 이른 날짜)로 올라 있고, 권장 대체는 `gemini-3.8-live`다. 모델이 종료되면 실시간 통화는 전부 Mock 텍스트 폴백으로 강등된다.

3.8은 같은 Live API지만 동작이 다르다(공식 모델 페이지 · 2026-09-15 갱신). 이 저장소에 닿는 변화는 셋이다.

1. **함수 호출 기본값이 비동기(`NON_BLOCKING`)다.** 2026-10-17 라이브 프로브에서 `behavior`를 생략하면 3.8은 도구 호출과 함께 **턴을 즉시 끝냈다**(`toolCall` → `generationComplete` → `turnComplete`, 같은 시각 ±42ms). 클라는 그 `turnComplete`를 사기범 턴 경계로 세어 지시 큐 드레인 · 전환 상태 재주입 · 백스톱 카운터를 한 번 더 돌린다.
2. **`turnComplete:true` 클라 콘텐츠가 진행 중인 생성을 무조건 끊는다.** 같은 프로브에서 사기범 발화 도중 타이핑 1건을 보내자 3.8은 77ms 뒤 `interrupted` + `turnComplete`를 보냈다. 2.5는 같은 입력을 **턴이 끝날 때까지 보류**했다가 응답했다(`interrupted` 0건). 이 앱은 타이핑 입력 · 문자 안내 지시 · 확인 지시를 모두 이 형태로 보낸다(`GeminiVoiceSession.tsx:749` · `:868` · `:885`).
3. 응답이 빨라졌다. 같은 대본에서 첫 마디(트리거 → 첫 오디오)는 2.5 **4,893~7,878ms**(오디오 앞에 thought 파트가 5~7초 온다) → 3.8 **878~951ms**, 사용자 발화 끝 → 첫 오디오는 2.5 **2,038~3,820ms** → 3.8 **187~1,360ms**(도구 없는 턴).

## Decision

**모델 상수를 `gemini-3.8-live`로 바꾸고, 2.5에서 성립하던 의미 두 가지를 명시적으로 고정한다: (1) 두 Live 도구 선언에 `behavior: BLOCKING`을 넣는다, (2) 클라는 `turnComplete:true` 콘텐츠를 모델 턴이 진행 중일 때 보내지 않고 다음 `turnComplete`까지 보류한다(한 번에 1건).**

| Option | Pros | Cons |
|---|---|---|
| **3.8 + BLOCKING 명시 + 클라 보류 큐(채택) ✅** | §59 도구 흐름 · 턴 카운터 · 전사 순서가 2.5와 같은 의미로 남는다. 프로브에서 3.8+BLOCKING은 도구를 **먼저** 부르고 결과 뒤에 "문자 보냈다"고 말했다(2.5는 말한 **뒤에** 불렀다). 2.5도 BLOCKING을 받아 모델 상수만 되돌리는 롤백이 가능하다 | 클라에 보류 큐(순수 함수 + 배선)가 생긴다. 보류된 지시는 한 턴 늦게 들어간다(2.5 서버 보류와 같은 지연) |
| 3.8 + 모델만 교체 | 1줄 변경 | ⛔ **기각.** 도구 호출마다 가짜 턴 경계가 생기고, 지시 · 타이핑이 사기범 말을 중간에 끊는다(프로브 실측) |
| 3.8 + `NON_BLOCKING` + `scheduling` 채택 | 3.8의 비동기 흐름을 그대로 쓴다 | ⛔ **이번에는 기각.** ADR-0015의 "결과를 받고 이어 말한다"가 무너지고 §59 응답 문면(`guidance`) 계약을 다시 짜야 한다. 기한(2026-11-17) 안의 전환과 섞지 않는다 — 별도 설계 대상 |
| `gemini-3.8-live-extended-thinking` | 배경 추론이 깊다 | ⛔ 기각. 비동기 전용(`BLOCKING` 불가)이고 지연이 커지는 방향이다 |

## Consequences

- Positive: 기한 전에 실시간 통화가 계속 동작한다. 첫 마디 · 응답 지연이 프로브 기준 크게 준다. 3.8은 thought 파트를 보내지 않아 SDK의 "non-data parts" 경고가 사라진다.
- Negative / accepted trade-offs: 소표본(모델당 2~3통화) 실측이다. 3.8 출력 전사에 일본어 조각 1건(`"취소될 수があります"`, 2통화 중 1통화)이 나왔다 — 같은 프로브의 2.5에서는 0건. 3.8은 발화 끝 187ms 만에 답한 사례가 있어(400ms 침묵 기준보다 빠르다), 말을 잠깐 멈춘 참가자가 반이중 게이트에 잘릴 위험이 2.5보다 크다. 셋 다 라이브 확인 항목으로 넘긴다(§70.9).
- Follow-ups required: 배포 순서는 **Hosting(클라 보류 큐) → Functions(3.8)** 고정이다(§70.9 G434). 2026-11-17 뒤에는 2.5로 되돌릴 수 없다 — 그 뒤의 퇴로는 Mock 강등뿐이다. `NON_BLOCKING` 채택 · 시스템 프롬프트의 "한국어로만" 1줄 · 출력 음량 최종값은 후속 결정(OQ-A89 · OQ-A90).
