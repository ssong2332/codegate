# ADR-0009: 신규 순간(확인 무력화)의 판정 반영 — 순간 신설이 아니라 **기존 순간 주석**

- Status: accepted
- Date: 2026-07-26
- Owner: architect
- DECISIONS.md entry: #39
- 관련: UX.md UF-011 · UX-031 · **D-51 판정표(⑤ 포함)** / PRD AC-071(·AC-072는 T80) / Architecture.md **§16.3** / OQ-U22·OQ-U25
- 관계: **ADR-0007을 뒤집지 않는다** — 전달 모델(앱 오케스트레이션 + 인과 역전)은 ADR-0007 그대로이며(§16.1), 본 ADR은 그 위에서 **"이 사건을 리포트 판정에 어떻게 싣는가"** 만 결정한다. §15.1.5 (5)("문자 이벤트는 `deceivedMoments`에 넣지 않는다")도 **뒤집지 않는다** — 문자는 여전히 표시 전용이다.

## Context

UX v1.12의 **D-51**은 서로 충돌하는 두 요구 사이에 판정 경계를 세웠다.

- **AC-071**은 확인 무력화 순간을 *"확인했는데도 속은 순간"* 으로 **리포트에서 짚으라**고 명문 요구한다.
- 반면 **§15.1.5 (5)** 는 (통화 중 문자에 대해) *"`deceivedMoments`를 건드리지 않는 표시 전용"* 을 **명시 금지 규칙**으로 세웠다. 이유는 승격이 **AC-062**(속은 순간 0건이면 되감기 진입점 없음)·**AC-068**(아카이브 항목)·**AC-010/011**(방어등급)을 연쇄로 흔들기 때문이다(§15.6 G22).

D-51은 이 충돌을 *"속은 순간 자격은 **참가자의 실제 응낙**이 있을 때만"* 이라는 규칙으로 풀고, **데이터 경로는 architect에 넘겼다**(D-51 Impact). 그런데 여기서 결정적인 사실이 하나 있다(실측):

> **확인 무력화의 "응낙"은 참가자의 대화 발화다.** 재연결된 상대의 요구에 참가자가 응하는 순간은 `analyzeConversation`이 이미 `scammer(i) ↔ user(i+1)` 짝짓기 + `COMPLIANCE_PATTERN`으로 **속은 순간으로 잡고 있다**(`functions/src/report/analyzeConversation.ts:136-164`). 즉 **이 순간은 이미 존재한다.**

따라서 진짜 질문은 "순간을 만들 것인가"가 아니라 **"이미 만들어진 순간을 어떻게 확인 무력화로 식별할 것인가"** 다.

## Decision

**확인 무력화는 새 순간을 만들지 않는다. `analyzeConversation` 산출이 끝난 뒤, 재연결 대사의 turnIndex보다 뒤에 있는 기존 순간에 `afterVerifyReconnect: true`를 얹고 `tactic`·`tacticCategory`·`correctAction`을 서버 소유 고정값으로 덮어쓴다. 순간의 개수·`turnIndex`·`timeLabel`·`wasDeceived`는 한 건도 바뀌지 않는다.**

| Option | Pros | Cons |
|---|---|---|
| **기존 순간 주석(채택) ✅** | 계상이 **단 한 곳**(`analyzeConversation`)에서만 일어난다 → 순간 수·방어등급·아카이브 항목 수·되감기 딥링크 인덱스가 **구조적으로 불변**. AC-071의 "짚는다"를 충족. 되감기·아카이브는 **코드 변경 0**으로 새 문구를 받는다(둘 다 `deceivedMoments`를 읽으므로) | 주석 로직이 리포트 생성 경로에 1겹 추가된다. 재연결 경계(어느 순간부터 "확인 이후"인가)를 **정확히** 정해야 한다(§16.3.2 판정 앵커·G28) |
| 확인 무력화 전용 순간을 `deceivedMoments`에 **추가** | 리포트에 항상 한 줄이 보장된다 | **같은 응낙이 두 번 계상된다**(대화 발화로 이미 잡힌 순간 + 추가 순간) → 아카이브 "3번 넘어갔습니다"가 부풀고, 방어등급(AC-010/011)이 왜곡되며, `getAnnotatedTurnIndexes`↔`deceivedMoments` 1:1 전제가 깨져 **되감기가 엉뚱한 순간을 연다**(§15.6 G16) |
| 문자와 동일하게 **표시 전용**으로만 두고 판정에서 제외 | §15.1.5와 완전 대칭, 가장 단순 | **AC-071 미충족** — *"확인했는데도 속은 순간으로 짚는다"* 가 문면 요구다. 게다가 그 순간은 어차피 `deceivedMoment`로 이미 잡혀 있는데 **"확인 이후"라는 사실만 잃는다**(참가자에게 가장 중요한 학습 포인트가 사라진다) |
| `wasDeceived`를 확인 시도만으로 뒤집기 | — | **G22 정면 위반.** D-51 ①/⑤(권유했으나 안 걸음 / 걸었으나 응하지 않음)에서 **속지 않은 참가자를 속았다고 판정**한다(AC-008/009 회귀) + AC-062 위반 |

부수 결정(같은 맥락이라 함께 못박는다):

1. **계상 단일성 규칙(일반 원칙).** *"하나의 응낙은 정확히 한 번만 계상된다."* 신규 순간 종류가 추가될 때, 그 응낙이 **대화 발화로 나타나면 주석**, **대화 밖(UI) 이벤트로 나타나면** 그때 비로소 순간 신설을 검토한다. **후자는 T80(AC-072 모의 앱 설치)의 결정 사항**이며, 어떤 형태로 결정하든 이 단일성 규칙은 지켜야 한다(§16.8 OQ-A9).
2. **덮어쓰기는 `tactic`/`tacticCategory`/`correctAction` 3개로 한정한다.** `tactic` 추정(`findMatchedTactic`)은 실시간 경로의 자유 생성 대사에서 매칭이 보장되지 않아 `"약화된 사기 수법"`/`other`로 떨어질 수 있다 — 이 순간의 수법은 **카탈로그가 만든 상황이라 이미 알고 있으므로** 추정에 맡기지 않는다.
3. **`correctAction` 덮어쓰기는 안전 요건이다.** `pickCorrectAction`의 첫 규칙이 `/확인|전화/`이고 그 문구가 *"…반드시 알고 있는 번호로 직접 전화해 사실을 확인하세요"*(`analyzeConversation.ts:176-179`)라, 방금 **확인 전화가 소용없던** 참가자에게 그대로 나가면 AC-071의 무력감 방지 요건을 훼손한다(§15.6 G27).
4. **`analyzeConversation`은 무변경이다.** 시그니처·입력·짝짓기 루프에 손대지 않는다(§15.6 G3 재발 금지). 주석은 **산출 뒤에 도는 순수 함수**이며, 확인 문서가 0건이면 리포트 산출이 도입 전과 **완전히 동일**해야 한다(필수 회귀 테스트).
5. **리포트는 여전히 세션당 정확히 1개다.** 주석·스냅샷은 `reports/{rid}` **최초 생성 시 1회**만 기록되고, 생성 이후 문서를 update하지 않는다(AC-007, `generateReportCore.ts` 멱등 early-return 무변경 — §15.6 G13과 동일 규칙).

## Consequences

- **Positive**
  - **AC-062·AC-007·AC-010/011·AC-068이 구조적으로 보호된다** — 순간 수가 변하지 않으므로 되감기 진입 조건·리포트 개수·방어등급·아카이브 항목 수가 **정의상** 흔들릴 수 없다.
  - 되감기(§15.2)·아카이브(§15.4)는 **한 줄도 고치지 않고** AC-071의 유효 대처를 받는다(둘 다 `deceivedMoments`를 단일 소스로 쓰기 때문).
  - D-51 판정표 ①②⑤가 **데이터 조건으로 1:1 번역**된다(§16.3.3 표) — QA가 판정할 기준이 코드와 같은 모양이다.
- **Negative / accepted trade-offs**
  - 재연결 경계(판정 앵커)가 **±1 오차에 민감**하다. 폴백 경로에서는 참가자가 말을 해야 재연결 대사가 나오므로, 경계를 표시 앵커로 잡으면 **재연결 전 순응까지 오분류**된다 — 그래서 판정 앵커를 **재연결 대사 자체의 turnIndex**로 별도 정의했고(§16.3.2), G21의 교훈대로 **에뮬레이터 실측**을 요구한다(§15.6 계열 G28).
  - 확인 시도가 있었지만 참가자가 응하지 않은 세션(D-51 ⑤)에서는 `deceivedMoments`가 비어 리포트의 "속은 순간" 목록에 아무것도 없다 — **표시 전용 `verifyTimeline`이 그 공백을 메운다**(그리고 리포트 타임라인 노출 조건을 넓히지 않으면 통째로 사라진다 — G30).
- **Follow-ups required**
  1. `functions/src/report/tacticCategory.ts`의 `verification_block` 규칙에 `확인[^]{0,6}무력화` 추가 — 안 하면 T83이 라벨을 저작하는 순간 드리프트 테스트가 깨진다(G29, **테스트를 완화하지 말 것**).
  2. `smsTimeline.ts`의 `resolveAnchor`를 export해 `verifyTimeline.ts`가 **같은 리졸버를 공유**한다(복제 금지 — G7과 동일 판단).
  3. 리포트 타임라인 노출 조건에 `|| verifyTimeline.length > 0` 추가(G30).
  4. `getAnnotatedTurnIndexes`에 확인 항목을 **넣지 않는다**(G16 그대로 — 넣으면 되감기 딥링크가 어긋난다).
  5. T80: 모의 설치(AC-072)의 응낙은 대화 밖 UI 이벤트라 본 ADR의 주석 방식이 그대로 성립하지 않는다 — **계상 단일성 규칙만 물려받아 별도 결정**할 것.
