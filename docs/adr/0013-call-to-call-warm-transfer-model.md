# ADR-0013: 통화→통화 전환은 "새로 걸기"가 아니라 **호 전환(넘겨주기)** 으로 재현하고, 원 화자 퇴장은 **모델에 도달하는 문자열 집합**으로만 강제한다

- Status: accepted
- Date: 2026-07-27
- Owner: architect
- DECISIONS.md entry: #52
- 관련: ADR-0007(앱 오케스트레이션 전달 모델 — 재적용, 무변경) · ADR-0009(순간 주석 — **무변경**) · ADR-0004(프롬프트·음성 서버 고정 — 이 ADR이 그 잠금을 전제로 받는다) · Architecture.md **§22**(정본) · §16(부분 대체 범위는 §22.1)

## Context

사용자가 라이브 사용 중 직접 신고했다(2026-07-27): 확인 무력화 흐름에서 **AI 화자가 겹친다.** 참가자가 안내받은 번호(`1500-0000`)로 확인을 시도하면 전환 화자(*"○○금융범죄대응센터 김철민 담당자입니다"*)가 등장하는데, **원 화자(김민수 수사관)도 계속 발화**한다.

같은 신고에서 사용자는 **기존 요구의 범위를 좁히는 정정**을 함께 냈다 — *"통화가 유지되어야 한다"* 는 **통화↔문자 사이에만** 적용되며, **통화→통화는 상담센터처럼 넘겨주는 형태**여야 한다.

원인은 모델의 드리프트가 아니라 **설계가 요구한 동작**이다(파일:줄 실측):

| # | 사실 | 근거 |
|---|---|---|
| 1 | `announceInstruction`이 원 화자에게 *"저는 끊지 않고 기다리겠습니다"* 라고 말하게 한다 → **원 화자의 세션 잔류가 프롬프트로 요구된다** | `functions/src/scenarios/verifyIntercept.ts:60`(및 `:118`) |
| 2 | `reconnectInstruction`은 *"참가자가 안내받은 번호로 확인 전화를 걸어 지금 막 연결됐다"* 로 **참가자의 신규 발신을 전제**한다 | 같은 파일 `:61,71,81,91,101,119` |
| 3 | 두 지시가 **같은 모델 세션에 공존**한다(하나는 잔류, 하나는 새 상대) | Gemini Live 단일 세션 — `functions/src/realtime/geminiProvider.ts:77-99` |
| 4 | 같은 패턴이 **카탈로그 6종 전부**에 복제돼 있다 | `verifyIntercept.ts:54-120`, 레지스트리 `:143-150` |
| 5 | 신규 발신 전제가 **스키마에도 박혀 있다** | `displayNumber`(`:35`, `/^\d{3,4}-0000$/`) · `reconnectedCallerLabel`(`:37`) |

핵심 질문은 *"원 화자 퇴장을 무엇이 보증하는가"* 였다. 프롬프트 지시만으로는 보증이 없고 — 이번 결함이 정확히 그 실패다 — **서버가 강제할 수 있는 지점이 있는지**를 먼저 실측해야 했다.

## Decision

**1. 전환 모델을 "호 전환(warm transfer)"으로 확정한다.** 사기범이 *"제가 확인 부서로 바로 연결해 드리겠습니다"* 로 받아 호를 넘기고, **원 화자는 통화에서 빠지며**, 전환 화자가 앞선 요구를 *"확인해 드렸다"* 는 형태로 이어간다. **참가자가 번호를 안내받아 새로 거는 형태는 폐기한다.** 세션·소켓·타이머는 유지되고 **화자만 교체된다.**

**2. 원 화자 퇴장을 강제하는 지점은 "모델에 도달하는 문자열 집합" 하나뿐이며, 그 집합은 정확히 3개다** — ① 상시 블록 `VERIFY_INTERCEPT_RULE`(시스템 프롬프트) ② `announceInstruction` ③ `reconnectInstruction`. 셋 다 서버 파일의 리터럴이므로 **전부 기계 검사 대상**으로 만든다. 다른 강제 후보(세션 중 시스템 프롬프트 교체 / 소켓 재연결 / 음색 전환 / 서버측 출력 필터 / 클라 화자 음소거)는 **전부 불가 또는 기각**이다(근거는 Architecture.md §22.2 표).

**3. 잔류 요구는 삭제로 끝내지 않고 "퇴장 규칙"으로 대체하며, 그 규칙은 상시 블록(system prompt)에 둔다.** 1회성 턴 주입은 다음 턴이면 컨텍스트 뒤로 밀리지만 시스템 프롬프트는 매 턴 선두에 있다 — 이 구조에서 얻을 수 있는 **최대 지속성**이다.

**4. `displayNumber`는 카탈로그에서 제거하고, 문서·리포트 스냅샷에서는 옵셔널로 낮춘다**(과거 리포트 무백필). 그 필드가 지키던 안전 검사 3종은 **카탈로그 전 필드 순회 게이트**로 승격해 대체한다 — 결과적으로 **검사 커버리지가 넓어진다**(현행은 3개 필드 하드코딩이라 신규 필드가 자동으로 검사를 빠져나갔다). `reconnectedCallerLabel`은 **유지**한다 — 전환 모델에서 원 화자 퇴장의 **유일한 시각적 보증**이다.

**5. 스키마·콜러블·컬렉션은 늘리지 않는다.** `placedAt`을 포함한 필드명은 **개명하지 않는다**(판정 앵커·주석 경계·멱등 규칙·리포트 `outcome`이 전부 그 이름에 매달려 있다). 의미만 *"참가자의 확인 시도"* 로 넓게 읽는다.

## Consequences

- **얻는 것**: 사용자가 신고한 결함의 **직접 원인(공존하는 두 전제)이 제거**되고, 그 제거가 **기계로 검증 가능**해진다(6종 전수 + 역검증). ADR-0009의 순간 주석 모델·§16.3의 기록/판정·§16.4의 유효 대처는 **한 줄도 바뀌지 않는다.**
- **⚠️ 보증하지 못하는 것**: **원 화자의 침묵은 보증되지 않는다.** 모델이 자발적으로 앞 페르소나로 되돌아가는 것을 막는 수단은 이 아키텍처에 없다. *"이제 화자가 겹치지 않는다"* 는 보고는 **금지**이며, 말할 수 있는 것은 *"겹침을 요구하던 지시가 사라졌고 퇴장 규칙이 상시로 들어갔으며 라이브 관찰에서 재현되지 않았다"* 까지다(OQ-A10으로 측정 등재).
- **경로 비대칭(정직 고지)**: 폴백(텍스트)은 매 턴 시스템 프롬프트를 재조립하므로 퇴장 규칙이 **매 턴 재삽입**되고, 실시간(Gemini Live)은 토큰 발급 시 **1회 고정**이다 — **주 경로가 구조적으로 더 약하다.**
- **훈련 목표가 이동한다**: 현행 교훈 *"내가 직접 건 확인 전화도 가로채진다"* → 전환 모델 교훈 *"상담원이 넘겨준 통화는 독립 확인이 아니다"*. **둘 다 실제 수법이지만 같은 교훈이 아니며**, 6종 전부가 전환 모델이 되므로 **전자의 재현은 라이브러리에서 0건이 된다.** AC-071 문면 처리((가) 제자리 수정 / (나) 신설 / (다) 무변경)는 **사용자 확정 사항**이고 architect 의견은 **(나) 권고 · (다) 차선 · (가) 비권고**다. **어느 결론이든 이 ADR의 설계와 완료 증거는 달라지지 않는다.**
- **소급 영향**: T83·T95의 병합·GO 판정은 **뒤집히지 않는다**(당시 문면·당시 설계대로 옳았다). 다만 (가)를 택하면 그들이 제출한 **완료 증거가 그 문면의 증거가 아니게 된다** — 그것이 (가)를 비권고하는 이유다.
- **되돌리는 법**: 두 모델을 공존시키려면 카탈로그 판별자 1개(`transferMode: "warm_transfer" | "dial_out"`)를 추가해 **값만 늘리는 형태**로 복원 가능하다. **지금은 만들지 않는다** — 쓰는 곳이 없는 판별자는 죽은 필드다(§0.1).
