## Goal
사용자 **본인의 목소리를 AI로 복제**해, "내 목소리로 가족에게 사기 전화가 가면?"을 직접 체험시키는 AI 금융사기 백신을 만든다. 사용자가 30초 목소리를 녹음하면 AI가 그 목소리로 가족 사칭 사기 전화를 앱 내 오디오로 재현하고("이렇게 감쪽같이 당한다"를 체감), AI 사기범과의 실시간 역할극 후 "어디서·언제 속았는지"를 짚는 취약점 리포트와 방어 훈련(게임화)을 제공한다. 약화된 실전 공격에 미리 노출시키는 예방접종(inoculation)형 서비스다.

**(v0.9 확장)** 훈련 범위를 보이스피싱에서 **메신저피싱(카카오톡형·문자메시지형)까지** 넓히고, 실제 사기의 전형인 **채널 간 에스컬레이션**(문자·메신저로 접근 → 의심하면 전화로 넘어옴)을 하나의 연결된 시나리오로 재현한다. 사용자는 유형을 고르면 그 유형의 시나리오가 드러나는 몰입형 흐름으로 훈련한다. 상세 요건은 MVP Scope #13~#17·AC-028~AC-037 참조.

**(v0.10 확장)** 여기에 (1) **사후 리플레이 해설**(끝나고 대화를 되짚으며 "여기 이 말이 사기 신호였어요"를 짚어 주는 교육 단계, AC-038), (2) **2인 소셜 훈련**(사용자1이 자기 목소리를 복제해 지인 사용자2에게 딥보이스 사기를 안전하게 체험시키는 비동기 챌린지 모델 — 딥보이스 사기의 실제 작동을 정면으로 체감시키는 핵심 흐름, AC-040~044)을 더한다. 2인 모델은 사용자2 사전 동의·복제 음성 유출 차단·강제 정체 공개·결과 열람 제한의 **4대 안전제약이 출시 전제조건**이다. 상세는 MVP Scope #18~#19·AC-038~AC-044 참조.

**(v1.4 재배치)** 보이스 clone(딥보이스) 체험은 이제 **"지인에게 보내기" 2인 챌린지로만 도달**한다(AC-057) — 자기 목소리로 자기에게 거는 자기 체험은 "그 목소리를 아는 사람이 받는다"는 딥보이스 착시가 성립하지 않아 배제됐다. 위 Goal 서술의 "본인 목소리 복제 딥보이스 체험"은 여전히 유효하되 그 전달 경로가 자기 체험 → 지인 챌린지로 옮겨진 것이다. Goal·차별점 1 문면과 플래그십 데모 시연 방식의 정합 갱신 필요 여부는 **OQ-33**.

### 해결하려는 문제
- 기존 안티사기 서비스는 탐지·차단(사후) 중심이거나, 고정 시나리오 재연 교육에 그친다. 사람들은 사기의 존재를 지식으로는 알아도, 실제 상황의 심리적 압박(권위·긴급·공포·가족애)을 겪어본 적이 없어 막상 당한다.
- 격차는 "지식"이 아니라 "경험·자각"에 있다. 특히 **본인 목소리가 얼마나 쉽게 탈취·악용되는지**를 신체적으로 자각할 방법이 없다.

### 근거 데이터 (조사 기준일 2026-07-21)

### 차별점 (참신점 3가지)
1. **본인 목소리 복제**로 위협을 신체적으로 자각(경쟁사는 고정 시나리오/타인 음성).
2. **가족 원격 훈련** — 자녀가 부모의 계정 생성 UI를 보조하고, 목소리 등록(녹음)은 반드시 부모 본인이 직접 수행(안전 기본값 확정, OQ-13 resolved → AC-020 정합). 부모가 안전하게 당해보고 리포트를 남긴다(리포트를 자녀가 열람 가능한지는 OQ-15 미확정). 자녀 보조 UI의 구체 권한 범위·MVP 실제 포함 여부는 OQ-3.
   - **발표 내러티브 강조 확정(2026-07-21), 단 Day1 빌드 범위는 미확장(본인 온보딩만).** 발표(피칭)에서는 이 "가족 원격 훈련"을 비중 있게 내세우기로 확정했으나, Day1 실제 빌드 범위는 지금 그대로 유지한다: 본인 온보딩만 구현하고, 자녀는 계정 생성 UI 보조 수준까지만(로드맵 방향성). **OQ-3(자녀 보조 UI의 MVP 실제 포함 여부)·OQ-15(자녀 리포트 열람 가능 여부)는 빌드 스코프 관점에서는 여전히 open이다.** 발표에서 강조한다는 방침과 빌드 스코프 결정은 별개 사안임(발표팀 가이드라인은 Risks 표 참조).
3. **게임화** — 사기 방어 등급, 신종 수법 자동 업데이트(구독 확장 방향).

경쟁사 대비: 국내 은행(우리 '하마터면', 신한 '보이스피싱제로')·해외 B2B(Brightside/Hoxhunt/Wizer/Doppel)·통신사앱(시티즌코난/익시오)은 고정 재연·기업 직원 대상·탐지 차단(사후)에 머문다. 우리는 개인·가족(어르신) B2C + 한국어 + 본인 목소리 감정 체험 + 사전 예방접종.

## 시나리오 수법 축 체계 (v1.6, 2026-07-25)
> **왜 축인가.** 지금 라이브러리는 "유형 1개 = 시나리오 1개"의 평면 나열이라 **무엇이 비어 있는지 볼 방법이 없다.** 축으로 분해하면 (1) 공백이 표로 드러나고, (2) 난이도가 "무엇을 바꾸는지"를 축으로 정의할 수 있으며, (3) 신규 시나리오 추가가 "하나 더 만들자"가 아니라 "이 좌표가 비었으니 채우자"가 된다. **이 섹션은 기획 프레임이며 스키마 설계가 아니다** — 축 값의 데이터 표현·저장 방식은 architect 소관.

### 난이도 재정의 — "무엇을 바꾸는가"
> **기존 AC-064~AC-067은 무변경으로 유효하다. 아래는 그 위에 얹는 재정의이며 AC-074로 규정한다.**

| 레버 | 초급 | 중급(현행 기준선) | 고급 |
|---|---|---|---|
| **L1 수법 노출도** | 전형 문구를 그대로 쓴다 | 현행 | 자연스러운 상담·안내 대화에 녹인다 |
| **L2 압박 지속성** | 의심하면 물러선다 | 한 번 더 밀어붙인다 | 물러서지 않고 **서로 다른 근거·절차로 재대응** |
| **L3 이탈 차단 깊이(축 D)** ⭐신규 | D축 수법 0~1개(D1 정도) | D1·D2·D5 | **D3 또는 D4를 최소 1개 포함** — 확인하겠다고 하면 막지 않고 **권한다**, 또는 절차·서류를 갖춰 의심 자체를 줄인다 |
| **L4 요구 도달 단계성** ⭐신규 | 처음부터 최종 요구 | 압박 후 최종 요구 | **무해해 보이는 선행 요구**(본인확인·조회용 앱 설치 등)를 먼저 통과시키고 최종 요구에 도달 |

- **⭐신규 L3·L4가 사용자 지적의 해소 지점이다.** 현행 고급은 L1·L2만 움직여 "같은 수법을 더 세게 말하는" 상태였다.
- **불변(AC-065 계승)**: 네 레버 중 어느 것도 안전장치·무해화 경계를 건드리지 않는다. **"고급 = 더 진짜 같은 압박"이지 "고급 = 더 진짜에 가까운 위험 정보"가 아니다.**
- **불변(협박 2종)**: `kidnapping-threat`·`reputation-blackmail-scam`에서 고급이 올리는 것은 **L3·L4뿐**이며, 구체적 폭력·신체 손상·성적 내용 묘사는 세 난이도 전부에서 금지다.

| AC-062 | (즉시 되감기·재연 드릴) 세션 종료 후 리포트의 "속은 순간"이 **1건 이상일 때**, 사용자는 그 순간 **하나**로 되돌아가 (1) 그 시점 앞뒤 맥락과 사기범의 문제의 발화, (2) 자신이 실제로 했던 답변을 확인하고, (3) **직접 다시 답한 뒤** 즉시 3단계 판정(잘 대응함 / 아직 위험함 / 판단 어려움) + 이유 + **그 순간의 올바른 대처**(AC-026의 `correctAction`)를 나란히 받는다. 입력은 **강제되지 않는다**(입력 없이 모범 대처만 보는 경로 제공). **속은 순간이 0건이면 되감기 진입점을 노출하지 않고** "속지 않았습니다"(AC-009)를 명시한 뒤 리플레이 해설(AC-038)로 안내한다 — "속을 뻔한 순간(near-miss)"은 현재 분석 산출물에 없으므로 **발명하지 않는다**(신설 여부는 OQ-34). **2인 챌린지의 사용자2에게는 강제 정체 공개(AC-042)와 강제 리플레이 해설을 마친 뒤의 선택 단계로만 노출**되며, 되감기가 그 강제 순서를 대체하거나 앞지르지 않는다. 판정 실패 시 조용히 넘기지 않고 실패 사실을 명시한 뒤 **모범 대처는 반드시 표시**한다. 과신("이제 안전/면역")·질책("또 틀렸습니다") 표현을 쓰지 않는다. |
| AC-063 | (즉시 되감기·AC-007 불변식 보호, 안전) 되감기는 **새 리포트를 생성하지 않고**, 원 리포트의 판정 결과(속았는지 여부·속은 순간 목록)를 **덮어쓰거나 변경하지 않는다** — **AC-007("종료된 모든 세션은 정확히 1개의 리포트를 생성한다")은 되감기 도입 후에도 그대로 성립해야 하며, 이를 깨는 구현은 채택하지 않는다.** 되감기는 원 세션을 재개하지 않는 **단발 평가**로, 새로운 사기 대사를 이어서 생성하지 않는다(대화가 계속되는 것이 아니라 한 턴 드릴이다). 표시되는 대화는 **마스킹된 transcript**만이며(AC-024), 판정·모범 대처 어디에도 실제 사기 실행 정보를 노출하지 않는다(AC-005/AC-013). 사용자의 새 답변은 기존과 동일하게 **데이터로 감싸 처리**되고 지시로 해석되지 않는다(AC-024). 되감기 시도 기록의 저장 여부·위치는 architect 소관이되, **어떤 저장 설계도 위 불변식을 깨서는 안 된다**(docs/UX.md OQ-U17). |
| AC-064 | (난이도·사용자 선택형 3단계) 사용자는 **시나리오를 확정한 직후, 세션(또는 챌린지) 생성 직전에** 훈련 강도를 **초급 / 중급 / 고급 중 하나**로 선택하며, 선택하지 않으면 진행할 수 없다(기본 강조값은 제공). **난이도는 시나리오 목록을 필터링하지 않는다** — 모든 시나리오가 3단계를 전부 지원하며 난이도 선택이 어떤 시나리오도 감추지 않는다. 선택된 난이도는 세션(또는 챌린지)에 함께 전달되어 **세션 화면·리포트·리플레이·실패 아카이브에 동일한 라벨로 표기**된다. 2인 챌린지에서는 발신자가 고른 난이도가 챌린지에 실려 **수신자의 사전 동의 랜딩(AC-040)에 표시**되고, 발신자에게는 고급 선택 시 "상대가 강한 압박을 겪게 됩니다"가 발송 전에 고지된다. 난이도 값이 하류로 전달되지 않은 예외 상황에서 **조용히 임의 난이도로 진행하지 않는다**(중급으로 폴백하되 그 사실을 사용자에게 표시). 난이도의 데이터 모델·프롬프트 조립 방식은 architect 소관(docs/UX.md OQ-U18). |
| AC-065 | (난이도·안전장치 무게이팅, 안전·필수) **난이도는 어떤 안전장치도 게이팅·약화·우회하지 않는다.** 사전 고지(AC-012)·명시적 동의(AC-017)·상시 종료(AC-006)·합성/모의 표식(AC-022/AC-032)·종료 고지·디스컬레이션(AC-015/AC-023)·생성물 폐기(AC-021)·PII/인젝션 방어(AC-024)·2인 4대 안전제약(AC-040/AC-041/AC-042/AC-043)·면책 고지(AC-047)·활성 챌린지 상한(AC-049)·결과 열람 범위(AC-043/AC-055)는 **초급·중급·고급에서 완전히 동일**하게 강제된다(AC-050의 "등급 무관 동일 강제" 원칙과 동형). **무해화 경계도 고급에서 완화되지 않는다** — 실계좌·실 기관·실 URL·운영 가능한 사기 절차 미노출(AC-005/AC-013/AC-032/AC-033)은 고급에서도 불변이며, **"고급 = 더 진짜 같은 압박"이지 "고급 = 더 진짜에 가까운 위험 정보"가 아니다**. 난이도가 바꾸는 것은 **압박 강도·요구 도달 속도·수법의 은밀함**뿐이다. 구현상 난이도 지시가 프롬프트 조립에서 가드레일·무해화 제약을 **밀어내지 않아야** 하며(가드레일이 마지막에 오는 기존 조립 순서 불변식 유지), 이 순서 불변식은 자동 테스트로 고정한다. 난이도별로 안전장치가 달라지는 설계는 **명시적으로 금지**된다. |

| AC-069 | (실패 아카이브·데이터 경계, 프라이버시·안전) 아카이브는 **본인 계정(uid) 소유 데이터만** 열람한다. **2인 챌린지의 사용자2(익명 수신자) 데이터는 어떤 형태로도 포함하지 않는다** — 익명 수신자에게는 계정 단위 누적이 성립하지 않으며, 발신자에게 수신자의 실패 이력이 누적 노출되는 경로를 만들면 결과 열람 제한(AC-043/AC-055)이 우회되기 때문이다. 이 제외는 협상 대상이 아니다. 세션 종료 시 폐기되는 합성 음성·생성물(AC-021)은 아카이브에서 **재생 경로가 존재하지 않으며** 텍스트 정보만 남는다. 실제 사기 실행 정보를 노출하지 않는다(AC-005/AC-013). **검색·기간/채널 필터·통계 차트·취약 유형 프로파일 대시보드는 포함하지 않는다** — 취약 지점 프로파일은 별도 제안(P-9, P2 로드맵)으로 관리되며 여기서 선구현하지 않는다(스코프 크립 방지). |

| AC-072 | (E3·모의 앱 설치·원격제어 재현의 무해화 하드 제약, 안전) 시나리오는 "앱을 설치하라 / 원격 지원을 허용하라"는 요구를 **하나의 진행 단계**로 재현할 수 있다. **단 다음은 어떤 형태로도 존재하지 않는다: 실제 설치 파일(APK 등)·실제 앱스토어 링크·실존 앱명·실제 OS 권한 요청·실제 기기 설정 변경·외부 네비게이션.** 재현은 **앱 내 모의 화면**(가짜 설치 진행 표시 등)으로만 이루어지고 "AI 훈련용 모의" 표식(AC-022/AC-032)이 노출되며, 참가자의 입력은 서버로 전송되지 않는다(AC-045와 동일 원칙, **신규 가짜 랜딩 화면을 별도 계열로 만들지 않고 기존 인앱 목업 경로를 재사용**해 안전 검증 경로를 이중화하지 않는다). 참가자가 모의 설치·원격 허용에 응한 순간이 세션 타임라인에 기록되어 리포트에서 **"이 순간 기기를 넘겨준 것"**으로 교육 포인트화된다(AC-026). |

### 원칙 (다른 모든 수익화 항목보다 우선 — AC-050으로 강제)
- **안전장치는 등급과 무관하게 전 사용자 동일 강제.** AC-040(사전 동의)·AC-041(유출 차단)·AC-042(정체 공개)·AC-043(결과 열람 제한) 및 기타 모든 보안·윤리 가드레일은 무료/유료/B2B/B2G 구분 없이 동일하게 적용된다. **유료화는 절대 안전장치를 약화·우회·게이팅하지 않는다**(AC-050).
- **핵심 안전훈련 콘텐츠는 무료 유지**: 보이스+메신저 **기본 시나리오 전체**, **리플레이 해설 기본**(AC-038)은 무료.

### B2B/B2G 채널 (개인 구독과 병행)
- **B2B**: 기업 임직원 정기 안티피싱 교육 라이선스 + 관리자 대시보드(이수율·취약유형 통계). ※ 관리자 대시보드는 기존 Out of Scope(개인 MVP 밖)였던 항목의 유료 채널 실체화.
- **B2G**: 지자체·복지관 대상 대량 좌석 라이선스 — **최종 사용자(어르신)는 무료, 기관이 비용 부담**. 취약계층 도달 미션과 정합.

### 로드맵 메모
- 등급별 기능 게이팅 로직·결제 연동(PG)·구독 상태 관리는 **별도 후속 계획**에서 태스크화한다(이번 Tasks.md T23~T40 범위 밖). 게이팅 구현 시 **AC-050(안전장치 게이팅 금지)을 게이트 조건으로** 검증해야 한다.

## Assumptions
- MVP는 웹(Next.js) 단일 채널, 텍스트 채팅 기반이며 사용자는 인터넷 연결 기기에서 텍스트를 읽고 입력하고 마이크로 30초 녹음할 수 있다.
- ElevenLabs Instant Voice Cloning API가 1~3분(본 스코프는 30초) 샘플로 사용 가능한 품질의 한국어 클론을 하루 내 산출한다(전날 리허설로 검증 — Risk 참조).
- 지속적 인격 롤플레이와 가드레일을 감당할 LLM(Claude/Gemini)을 세션당 합리적 비용/지연으로 사용할 수 있다.
- 사용자는 자발적 훈련 대상이며 공격자가 아니다.
- **자녀 대리설정 시, 목소리 녹음은 반드시 본인(등록 대상자)이 직접 수행하며 자녀는 계정 생성 UI 조작만 보조한다. 실제 녹음 버튼은 본인이 누른다**(OQ-13 확정). 따라서 동의 주체는 본인, 데이터 소유권은 본인 계정 소유다(OQ-11 확정).
- 1차 언어·시장은 한국어/한국(확정, OQ-7 resolved).
- **(메신저 확장·추정) 보이스 단계는 기존 실시간 음성 파이프라인·통화 셸(UX-014, `VoiceProvider`, LLM 어댑터)을 재사용할 수 있다.** 에스컬레이션은 "새 통신 스택"이 아니라 기존 세션의 단계 전이로 구현 가능하다고 가정(추정 — architect가 세션 모델·상태 전이 접합점을 확인·확정해야 함).
